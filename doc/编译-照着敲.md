## 二、先确认离线包已正确解压

假设你把所有文件放在 `D:\IQmol`，源码目录是 `D:\IQmol\IQmol-src`。

### 2.1 四包解压顺序（顺序错了会白干）

1. `IQmol-submodules.tar.gz` → 解压到 `D:\IQmol\IQmol-src\modules\`
2. `IQmol-openbabel-deps.tar.gz` → 解压到 `D:\IQmol\IQmol-src\modules\openbabel\`
3. `IQmol-openbabel-fix.tar.gz` → 解压到 `D:\IQmol\IQmol-src\modules\openbabel\`
4. `IQmol-openbabel-formats-fix.tar.gz` → 解压到 `D:\IQmol\IQmol-src\modules\openbabel\`

> **警告**：步骤 3、4 会覆盖 / 增补 `modules/openbabel/` 下的文件。若你先解压了 4 再解压 1 或 3，补丁会被覆盖回旧版，configure 必崩。顺序必须按上表。

**必须用 MINGW64 终端的 tar 命令解压**：

```bash
cd /d/IQmol/IQmol-src
tar -xzf ../IQmol-submodules.tar.gz
cd modules/openbabel
tar -xzf ../../IQmol-openbabel-deps.tar.gz
tar -xzf ../../IQmol-openbabel-fix.tar.gz
tar -xzf ../../IQmol-openbabel-formats-fix.tar.gz
```

> 不要用 360 压缩、7-Zip、WinRAR 的图形界面解压 `.tar.gz`，它们会**静默丢文件**（已反复验证）。

### 2.2 快速检查文件是否齐全

在 MINGW64 终端执行：

```bash
cd /d/IQmol/IQmol-src
# 检查子模块聚合脚本
ls -1 modules/CMakeLists.txt
# 检查 OpenBabel 关键格式源文件（如果缺失，说明解压不完整）
ls -1 modules/openbabel/src/formats/xml/pubchem.cpp
ls -1 modules/openbabel/src/formats/json/chemdoodlejsonformat.cpp
ls -1 modules/openbabel/src/formats/json/pubchemjsonformat.cpp
# 检查 external 依赖
ls -1 modules/openbabel/external/maeparser-v1.2.3/README.md
ls -1 modules/openbabel/external/coordgen-master/README.md
ls -1 modules/openbabel/external/rapidjson-1.1.0/readme.md
# 检查 libinchi 和 test（fix 包补充的内容）
ls -1 modules/openbabel/src/formats/libinchi/ichidrp.h
ls -1 modules/openbabel/test/CMakeLists.txt
```

上面 9 条命令都应该出现文件路径，**任何一条提示 "No such file or directory"，先回去检查包是否解压完整/顺序是否正确**。

## 三、推荐方式：一键脚本

```bash
cd /d/IQmol/IQmol-src
bash ./scripts/build_windows.sh
```

脚本会自动：

1. 补全缺失的 `modules/CMakeLists.txt`；
2. 检测 CMake 4.x 并自动下载 portable CMake 3.31 到 `.tools/`；
3. configure（首次大约 1~5 分钟）；
4. 编译（首次大约 20~40 分钟）。

### 3.1 脚本的增量行为

脚本默认**增量**：

- 如果 `build/` 里已有 `CMakeCache.txt`，再次运行会**跳过 configure 直接编译**；
- 编译中断了重跑，会继续编剩下的 `.o`，不会从头开始。

**除非你要换 CMake 参数，否则不要删 `build/`**。删一次就要重新 configure 一次，慢得没意义。

### 3.2 常用用法

| 命令 | 作用 |
|------|------|
| `bash ./scripts/build_windows.sh` | 增量编译（推荐日常用） |
| `bash ./scripts/build_windows.sh --clean` | 删掉 `build/` 从零 configure（慢） |
| `JOBS=8 bash ./scripts/build_windows.sh` | 强制用 8 线程编译 |
| `CMAKE_BIN="D:/cmake-3.31.6/bin/cmake.exe" bash ./scripts/build_windows.sh` | 指定已下载的 CMake 3.31 |

### 3.3 如果提示缺 `modules_CMakeLists.txt`

把交付的 `modules_CMakeLists.txt` 放到 `IQmol-src/scripts/` 同一目录，或脚本会从 GitHub 拉取。网络不稳时请手动放置。

## 四、手动命令方式（适合排查问题）

如果你不想用脚本，按下面顺序敲：

```bash
# 1. 进入源码目录
cd /d/IQmol/IQmol-src

# 2. 确认用 CMake 3.31.x，而不是 4.x
#    若系统是 CMake 4.x，到 .tools/ 里找脚本自动下载的 portable 版
cmake31="D:/IQmol/IQmol-src/.tools/cmake-3.31.6/bin/cmake.exe"
"$cmake31" --version   # 应显示 3.31.x

# 3. 新建/进入构建目录（如果已存在且有 CMakeCache.txt，直接进去 make）
mkdir -p build
cd build

# 4. 首次 configure（出现 -- Configuring done 才算完）
"$cmake31" .. \
  -G "MinGW Makefiles" \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="/d/msys64/mingw64" \
  -DCMAKE_CXX_FLAGS="-fpermissive -std=gnu++17 -Wno-deprecated" \
  -DCMAKE_MAKE_PROGRAM="mingw32-make" \
  -DBOOST_ROOT="/d/msys64/mingw64" \
  2>&1 | tee config.log

# 5. 编译（并行度按你 CPU 核数，建议 4~8）
mingw32-make -j4 2>&1 | tee make.log
```

configure 成功后，`build/` 目录里会生成 `CMakeCache.txt`。以后只要不删这个目录，**直接进去 `mingw32-make -j4` 即可**，不要再重跑 `cmake ..`。

---

## 五、编译省时的三条铁律

1. **首次 configure 慢是正常的**（1~5 分钟），因为它要调用 MinGW 编译大量小程序做特性检测；后续只要保留 `build/`，就不会再花这个时间。
2. **不要习惯性 `rm -rf build/`**。这是用户最容易踩的坑：删一次就要重新 configure 一次。
3. **并行度 `-j4` 到 `-j8` 为宜**。开满（如 `-j32`）容易因单编译单元 1~2GB 峰值内存而 OOM，反而更慢。

## 六、编译成功后拿到什么

在 `D:\IQmol\IQmol-src\build\` 下：

- `IQmol.exe`：主程序；
- `translations/zh_CN.qm`：中文翻译文件。

### 6.1 Windows 下还要复制 Qt 运行时 DLL

Windows 版不能直接双击跑，需要把 Qt 依赖复制到 `IQmol.exe` 同级目录。在 MINGW64 终端执行：

```bash
cd /d/IQmol/IQmol-src/build
windeployqt --release IQmol.exe
```

> 若 `windeployqt` 不在 PATH，一般位于 `D:/msys64/mingw64/bin/windeployqt.exe`，先把它加到 PATH：`export PATH="/d/msys64/mingw64/bin:$PATH"`。

这会生成 / 复制：

- `iconengines/`、`platforms/`、`styles/`、`translations/` 等子目录；
- `Qt5Core.dll`、`Qt5Gui.dll`、OpenSSL/ANGLE 等一堆 DLL。

### 6.2 中文翻译文件位置

`build/translations/zh_CN.qm` 是编译时自动生成的。用 `windeployqt` 后，再执行：

```bash
mkdir -p translations
cp translations/zh_CN.qm translations/zh_CN.qm 2>/dev/null || cp ../translations/zh_CN.qm translations/zh_CN.qm
```

确保 `IQmol.exe` 同级有 `translations/zh_CN.qm`。程序启动时会优先加载这里的翻译。

## 七、常见失败与排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `cmake ... CMP0042 OLD` 报错 | 用了 CMake 4.x | 改用 `build_windows.sh` 自动下载的 3.31，或手动指定 portable CMake 3.31 |
| `add_subdirectory given source "libinchi" not an existing directory` | fix 包没解压或顺序错了 | 重按顺序解压 `IQmol-openbabel-fix.tar.gz` |
| `ADD_CUSTOM_TARGET cannot create target "uninstall" ... already exists` | fix 包没覆盖到 openbabel/CMakeLists.txt | 同上，确认 fix 包覆盖了 `modules/openbabel/CMakeLists.txt` |
| `No SOURCES given to target: pubchem / xmlformat / ...` | formats 包没解压 / 解压丢文件 | 重按顺序解压 `IQmol-openbabel-formats-fix.tar.gz`，并检查 `src/formats/xml/`、`src/formats/json/` |
| `babelconfig.h: No such file or directory` | 根 CMakeLists 没打好补丁 | 确认源码是最新 `master`（补丁已在仓库里） |
| 编译一半报错，第二次直接跑又好了 | 大概率 MinGW 文件锁 / 并行问题 | 单线程重跑：`mingw32-make -j1` 或重跑脚本 |
| 编译成功但界面还是英文 | 缺少 `translations/zh_CN.qm`，或程序未把它放到可执行文件同级 | 见 6.2 |
