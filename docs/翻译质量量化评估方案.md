# IQmol 汉化版翻译质量量化评估（TQA）

> 本文档给出**可运行**的翻译质量量化评估方案，并报告 IQmol-for-Chinese
> 在基线 `ea322f2`（上游 `af7ff60`）上的**实测**结果。
>
> 工具：`scripts/i18n/tqa.py`　验收：见文末「实测报告」

---

## 一、设计原则

不用单一「翻译完成率」评价质量。采用加权六维模型：

```
TQA = 100 − ( w1·P1 + w2·P2 + w3·P3 + w4·P4 + w5·P5 + w6·P6 )
```

| 指标 | 含义 | 权重 |
|---|---|---:|
| P1 | 源码—翻译漂移 | 20 |
| P2 | 翻译资产完整率 | 20 |
| P3 | QM 交付有效度 | 15 |
| P4 | 术语一致性 | 15 |
| P5 | 界面可用性 | 15 |
| P6 | 语义质量 | 15 |

四条原则：

1. **「TS 条目完成」≠「界面中文完成」**；
2. **「英文残留」不是唯一缺陷类型**；
3. **准确率不能代替一致性、完整性、可运行性与界面可用性**；
4. **化学术语最终由计算化学人员裁决**，不由自动化规则独立判定正确。

---

## 二、六层证据链

```
源码可翻译文本 → TS 翻译资产 → 术语规范 → QM 运行时资源 → UI 运行时抽样 → 用户认知结果
```

| 层级 | 核心指标 | 自动化程度 |
|---|---|---|
| 源码 | 国际化覆盖率、漂移率 | ✅ 全自动（lupdate） |
| TS | 完成率、过期率、缺失率 | ✅ 全自动（XML 解析） |
| 术语 | 一致率、冲突率 | ✅ 词典比对（裁决需人） |
| QM | 生成率、加载率、命中率 | 🟡 生成/条目可自动；加载/命中需运行期 |
| UI | 中文覆盖率、截断率 | 🟡 动态文本可自动；截图需运行期采样 |
| 用户 | 任务成功率、理解准确率 | ❌ 需受控用户测试 |

> **本工具实现的边界**：P1 / P2 / P3(生成与条目部分) / P4 / P5(动态文本部分) 全自动；
> **P6 与 QM 加载率、界面命中率不臆造分数**，输出「未测量」并在总分中按有效权重归一，
> 避免用虚假满分掩盖未测维度。

---

## 三、各指标定义

### P1 源码—翻译漂移 `D_t = N_drift / N_source`

以 `lupdate -extensions C,ui src/` 实时提取为基准，与仓库 `zh_CN.ts`
按「上下文 + 源文本」匹配，统计新增/修改/删除/失配条目。

| 等级 | 漂移率 |
|---|---:|
| 优秀 | ≤1% |
| 可接受 | 1%~5% |
| 需整改 | 5%~15% |
| 不可接受 | >15% |

> ⚠️ **本项目特有陷阱（已实测确认）**：`lupdate` 只能看到 `src/` 下的 `tr()`。
> 而 `FragmentTable` 等 **369 条条目由本仓库工具注入**（片段库名、运行时数据），
> 源码中不存在。若把它们算作漂移，会得到 313 条「假漂移」。
> 本工具的判定依据是 **`<location>` 标记**：无 location 即工具注入，
> **不计入漂移**。实测排除后漂移率 = **0.00%**，与事实相符。

### P2 翻译资产完整率

```
Q_asset = 100 − ( 100·M_t + 70·O_t + 20·I_t )      （<0 记 0）
```

- `M_t` 未翻译率 = (空译文 + 未完成) / 总数，权重 100
- `O_t` 过期率 = (obsolete + 源文本变更) / 总数，权重 70
- `I_t` 缺少必要上下文（translator comment / 消歧）率，权重 20

### P3 QM 交付有效度

`G_qm` 生成率、`V_qm` 条目有效率（由 `lrelease` 实跑校验）、
`L_qm` 加载率、`H_qm` 命中率。后两项需运行期采样。

### P4 术语一致性

以 `scripts/i18n/known_translations.json` 为标准词典，检测：
同一英文源的中文译法是否与词典冲突。按风险加权：

| 风险 | 类型 | 权重 |
|---|---|---:|
| 致命 | 译错导致计算参数/命令/文件含义改变 | 100 |
| 严重 | 高频术语前后不一致 | 50 |
| 一般 | 风格、大小写、标点不统一 | 10 |
| 轻微 | 不影响含义的表达差异 | 2 |

**关键术语**：方法/基组/电荷/自旋多重态/收敛/优化/频率/振动/轨道/表面/
输入输出导出提交/错误失败取消。

### P5 界面可用性

可自动部分：
- **动态文本格式合规率** `F_c`：占位符数量与顺序、HTML 标签平衡、中文半角标点
- 英文残留率、截断/重叠率 → 需运行期 UI 采样

> **检测器自我校准**：本工具初版把 `<!DOCTYPE HTML ...>` 这类 HTML 骨架
> 误判为「中文半角标点」（4 条假阳性）。已修正为**仅当源文本为纯自然语言时**
> 才检查标点（源含 HTML 标签/实体/URL 则跳过）。修正后错误数 0。

### P6 语义质量（需人工）

`A_s` 人工语义准确率，四级评分：无错误 0 / 轻微 1 / 严重 10 / 致命 100。
须至少两名审校者（一名中文审校 + 一名计算化学），分歧由第三人裁决。
**本工具不自动评分。**

---

## 四、阻断项（单项否决）

即使总分高，出现以下任一即阻断发布：

- 致命术语错误
- QM 无法加载 / 未生成
- 主菜单或关键对话框仍为英文
- 错误信息乱码
- 关键参数提示可能导致错误计算
- 控件文本严重截断致操作无法完成
- 未完成翻译 / 空译文不为 0

### 5.1 该分数如何解读（重要）

**99.94 不等于「汉化质量接近完美」**，它只说明**已测量维度**表现良好：

| 已证明 | 未证明 |
|---|---|
| TS 无未完成/空译文 | 中文在运行界面上**是否真的显示** |
| QM 可生成、条目数正确 | QM 是否被程序**成功加载** |
| 源码与 TS 无漂移 | 界面**是否有布局截断/重叠** |
| 动态文本格式无缺陷 | 译文**语义是否正确**（需人工） |
| 术语与词典高度一致 | 用户**能否正确完成任务** |

> 要覆盖右列，须补 W4 运行时采样（界面树遍历 + 截图）与人工审校。
> 本工具已预留 P3 的 `L_qm`/`H_qm` 与 P6 接口，未测时输出 `None`
> 并在总分中剔除其权重，**不以满分冒充已测**。

### 5.2 本次评估发现的真实问题

**术语冲突 7 条**（P4），均为词典与 TS 实际用词不一致：

| 上下文 | 源文本 | 词典期望 | TS 实际 |
|---|---|---|---|
| MainWindow | `Open Recent` | 打开最近 | **最近打开** |
| MainWindow | `Gromacs Setup` | Gromacs 设置 | **GROMACS 设置** |
| MainWindow | `Edit Gromacs Config` | 编辑 Gromacs 配置 | **编辑 GROMACS 配置** |
| MainWindow | `Edit Gomacs Server` | 编辑 Gromacs 服务器 | **编辑 GROMACS 服务器** |
| MainWindow | `Fill Valencies With Hydrogens` | 用氢原子填充化合价 | **用氢饱和化合价** |
| MainWindow | `Network access available` | 网络连接可用 | **网络可用** |
| MainWindow | `Only one molecule can be visible...` | 原子重新编号时只能显示一个分子。 | **重新编号原子时仅可显示一个分子。** |

**判定**：`Gromacs` vs `GROMACS` 属**大小写不统一**（一般级，权重 10）——
建议统一为 `GROMACS`（官方写法），并同步更新词典。
`Open Recent` / `Network access available` 等属**表述差异**（轻微级），
二者语义均正确，建议**保留 TS 现译并更新词典**（现译更简洁自然）。

## 六、用法

```bash
# 人类可读报告（默认含 lupdate 漂移检测）
python3 scripts/i18n/tqa.py

# 快速模式（跳过 lupdate，仅 TS/QM/术语/格式）
python3 scripts/i18n/tqa.py --no-lupdate

# CI：有阻断项则非 0 退出
python3 scripts/i18n/tqa.py --gate --no-lupdate

# 机器可读 + 落盘（用于趋势对比）
python3 scripts/i18n/tqa.py --json --save reports/tqa-$(date +%F).json
```

> 是否引入新硬编码字符串、是否改变审校规则。
