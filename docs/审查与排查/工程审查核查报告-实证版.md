## 一、F1：指纹函数变量复用缺陷（已修复）

### 1.1 缺陷确认

`scripts/build_windows.sh` 的 `_cfg_fingerprint()`（原第 391–393 行）：

```bash
if grep -q 'STATIC_MAEPARSER' "$_cm" 2>/dev/null; then _ms=1; fi   # line 391
# 是否定义 STATIC_COORDGEN（coordgen 同类缺陷的预防性修复）
if grep -q 'STATIC_COORDGEN' "$_cm" 2>/dev/null; then _ms=1; fi   # line 393 ← 错误：复用 _ms
...
echo "... MAEPARSER_STATIC=$_ms ..."   # 指纹串无 COORDGEN 独立标志
```

### 1.2 影响面修正（不同于原审查报告）

原报告称会出现「误触发重配 **或** 漏掉重配」两种可能。**实证分析：只会「漏报」。**

`_ms` 是布尔 0/1，两个检测都只会把它置 1，不存在被置 0 误判的路径。因此：

| 变更场景 | 旧指纹是否变化 | 后果 |
|---|---|---|
| 删除 `STATIC_COORDGEN`，保留 `STATIC_MAEPARSER` | **否** | 该重配时未重配（漏报） |
| 删除 `STATIC_MAEPARSER`，保留 `STATIC_COORDGEN` | **否** | 漏报 |
| 两个宏**同时**消失 | 是 | 正常 |

### 1.3 修复内容

```bash
local _bs=0 _wa=0 _ms=0 _sc=0 _sm=0 _as=0        # 新增 _sc
...
if grep -q 'STATIC_COORDGEN' "$_cm" 2>/dev/null; then _sc=1; fi   # 改用独立变量
...
echo "BUILD_SHARED_SYNC=$_bs WHOLE_ARCHIVE=$_wa MAEPARSER_STATIC=$_ms COORDGEN_STATIC=$_sc OB_SRC_ADDITIONAL=$_as OB_ROOT_PATCHED=$_sm"
```

### 1.4 功能验证（三场景对比）

| 场景 | 修复后指纹 | 旧版 | 结论 |
|---|---|---|---|
| A：两宏都在 | `MAEPARSER_STATIC=1 COORDGEN_STATIC=1` | `=1` | ✅ |
| B：只删 COORDGEN | `MAEPARSER_STATIC=1 COORDGEN_STATIC=0` | `=1`（无变化→漏报） | ✅ **能区分** |
| C：只删 MAEPARSER | `MAEPARSER_STATIC=0 COORDGEN_STATIC=1` | `=1`（无变化→漏报） | ✅ **能区分** |

## 二、F2：裸 `-Wl` 回退的链接器兼容性（已修复）

### 2.1 缺陷确认

`CMakeLists.txt` 原第 542–546 行（`else()` 分支）：

```cmake
else()
   # 低版本 CMake 降级：裸旗标顺序不保证, 但至少不中断配置
   target_link_libraries (${targetName}
      -Wl,--whole-archive openbabel -Wl,--no-whole-archive
   )
endif()
```

`-Wl,--whole-archive` 是 **GNU ld 专有旗标**；非 GNU 链接器（MSVC `link.exe`、`lld-link`）会报错。且该分支**只检查 CMake 版本**，不检查链接器类型。

### 2.2 触发条件评估（说明优先级不高的原因）

裸旗标分支触发需**同时满足**：`WIN32` + `NOT BUILD_SHARED_LIBS` + `TARGET openbabel` + `CMAKE_VERSION < 3.24`。
而项目 Windows 静态路径**当前仅支持 MinGW-w64（GNU ld）**，故现存路径不受影响；风险仅在「未来引入 MSVC 且 CMake<3.24」叠加时显现。

### 2.3 修复内容

在 `else()` 分支内新增链接器检测，非 GNU ld 时 **fail-fast**：

```cmake
set(_iqmol_gnu_ld FALSE)
if (MINGW OR MSYS)
   set(_iqmol_gnu_ld TRUE)
elseif (CMAKE_LINKER MATCHES "(^|[/\\\\])ld(\\.exe)?$")
   set(_iqmol_gnu_ld TRUE)
endif()
if (_iqmol_gnu_ld)
   target_link_libraries (${targetName} -Wl,--whole-archive openbabel -Wl,--no-whole-archive)
   message(STATUS "[IQmol] CMake < 3.24 降级为裸 -Wl,--whole-archive (链接器: ${CMAKE_LINKER})")
else()
   message(FATAL_ERROR "[IQmol] 当前链接器 '${CMAKE_LINKER}' 不是 GNU ld, ... 请升级 CMake 到 >= 3.24, 或改用 MinGW-w64 (GNU ld) 工具链。")
endif()
```

### 2.4 功能验证（四种链接器）

| `CMAKE_LINKER` | 检测结果 | 正确性 |
|---|---|---|
| `/usr/bin/ld` | GNU LD: **yes** | ✅ |
| `C:/msys64/mingw64/bin/ld.exe` | GNU LD: **yes** | ✅ |
| `/fake/link.exe`（MSVC） | GNU LD: **no** → 触发 FATAL_ERROR | ✅ |
| `/fake/lld-link.exe` | GNU LD: **no** → 触发 FATAL_ERROR | ✅ |

## 三、F4：生成器一致性检查（已新增）

### 3.1 背景

`build_windows.sh` 固定使用 `-G "MinGW Makefiles"`。若 `build/` 曾由 Ninja / MSYS Makefiles / VS 等生成器创建，`CMakeCache.txt` 中的 `CMAKE_GENERATOR` 与将要用者不符，CMake 会报 `generator ... does not match the generator used previously`。

### 3.2 新增内容

在 `NEED_CONFIG` 判定之后插入生成器检查，并提供 `--recreate-generator` 选项自动清理重建：

```bash
EXPECTED_GEN="MinGW Makefiles"
if [ -f "$BUILD_DIR/CMakeCache.txt" ]; then
  CACHED_GEN="$(sed -n 's/^CMAKE_GENERATOR:INTERNAL=//p' "$BUILD_DIR/CMakeCache.txt" | head -1)"
  if [ -n "$CACHED_GEN" ] && [ "$CACHED_GEN" != "$EXPECTED_GEN" ]; then
    if [ "$RECREATE_GENERATOR" = "1" ]; then
      rm -rf "$BUILD_DIR" && mkdir -p "$BUILD_DIR" && NEED_CONFIG=1
    else
      echo "!! [generator] build/ 由 '$CACHED_GEN' 生成，与 '$EXPECTED_GEN' 不一致..."
      echo "   a) rm -rf \"$BUILD_DIR\";  b) 使用 --recreate-generator"
      exit 1
    fi
  fi
fi
```

### 3.3 功能验证

| 场景 | 行为 | 正确性 |
|---|---|---|
| 缓存 = `Ninja` | 拒绝并给出处置建议，`exit=1` | ✅ |
| 缓存 = `MinGW Makefiles` | 放行，`exit=0` | ✅ |
