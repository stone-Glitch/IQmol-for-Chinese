# IQmol 中文版推广视频 · 拍摄分镜清单

> 用途：逐镜头给出可直接喂给 `scripts/video/record_virtual_display.sh`（或其对话框扩展版）执行的 `xdotool` 序列、时长、输出文件名。
> 前置：虚拟显示已常驻（Xvfb :99 + openbox），IQmol 二进制位于 `build-video/IQmol`。
> 硬约束：**键盘合成事件不可用 → 所有导航走鼠标**；菜单 x 坐标随窗口宽度浮动，录制前须一次现场校准（见附录）。
> 路径约定：下文所有路径与命令均**假设当前目录为仓库根目录**；输出 mp4 落盘后自行搬运到 `build-video/out/`。

## 2. 逐镜头操作序列

### 2.1 S3-EN / S3-ZH —— 原版英文 → 中文硬切

> ⚠️ **环境变量切英文无效**（2026-10-02 实测）：
> `LANGUAGE=en_US.UTF-8 LANG=en_US.UTF-8` 启动**仍然加载中文翻译**——
> 本项目早期 4 次录制日志全是 `Loaded translation: "zh_CN"`，也就是说「中英对照」素材
> 一直是中文对中文，白录。IQmol 的语言取自 **QSettings**，不是环境变量。

```bash
CONF=/root/.config/iqmol.org/IQmol.conf

# ── 英文版：写 QSettings Language=en ──
printf 'Language=en\n' >> "$CONF"
./build-video/IQmol src/Parser/test/samples/viagra.xyz &
sleep 5
grep -q 'No translation file found for: "en"' <logfile> || echo "❌ 英文未生效，中止"   # 权威判据
ffmpeg -y -f x11grab -s 1920x1080 -r 25 -i :99.0 -t 1.5 -c:v libopenh264 shot_3_en.mp4
pkill -x IQmol; sleep 1

# ── 中文版：先删 Language 键，否则会沿用英文状态 ──
sed -i '/^Language=en$/d' "$CONF"
./build-video/IQmol src/Parser/test/samples/viagra.xyz &
sleep 5   # 等 [i18n] Loaded translation: "zh_CN"
ffmpeg -y -f x11grab -s 1920x1080 -r 25 -i :99.0 -t 1.5 -c:v libopenh264 shot_3_zh.mp4
pkill -x IQmol
```

> **收尾必做**：录制结束后确认 `Language` 键已删除（`grep -i '^Language' "$CONF"` 应无输出），
> 否则后续所有录制都会沿用上一次的语言，且极难察觉。

> 后期把 `shot_3_en.mp4` 与 `shot_3_zh.mp4` 做 1–2s 硬切，即「原版英文 → 中文界面」冲击力镜头。

## 3. 附录：一次现场坐标校准

菜单栏 x 坐标因字体 / 窗口宽度不同而变化，录制前跑一次，将读到的 x 回填到上面的 `<..._x>` 占位符：

```bash
WIN=$(xdotool search --name IQmol | head -1)
xdotool getwindowgeometry $WIN          # 拿窗口左上角与尺寸
# 手动把指针移到各菜单标题中心，记录 x（menubar_y 一般 ≈ 30）：
xdotool mousemove 560 30; xdotool getmouselocation   # 构建
xdotool mousemove 640 30; xdotool getmouselocation   # 计算
# 下拉子项：先点开菜单，再把指针移到目标子项中心记录坐标
```

工具栏「构建」C 按钮坐标见下方 3.1 节（无 WM 环境实测 **(262, 58)**）。
⚠️ 旧文档写的 `(265,50)` 是**在 openbox 环境下测的**，因22px 标题栏偏移而不准，
已废弃。若在带 WM 的环境录制，请先按 3.1 节坑 1 处理。

## 3.1 虚拟屏录制的三个致命坑（2026-10-02 实测踩坑记录）

⚠️ 下面三条是本项目录制失败三次后定位到的真因，**改动录制脚本前必读**。

### 坑 1：openbox 会吃掉所有指针事件（最隐蔽）

openbox 给IQmol 窗口加了标题栏装饰后，会额外创建一个 `1922x1075` 的 frame 窗口
（`xwininfo -id <IQmol_WID>` 可见 `Corners: +-1+-22`）。该 frame 位于 IQmol 客户区
**之上**，导致：

```bash
xdotool mousemove 266 58
xdotool getmouselocation      # → window:2104896（frame），而不是 IQmol 的 WID
```

**所有点击、悬停都打在装饰框上，IQmol 收不到任何事件**，表现是"坐标怎么试都不对"。

诊断命令（判断事件到底送给谁）：
```bash
xdotool getmouselocation   # 看 window: 字段是否等于 IQmol 的 WID
```

**修复：录制时不要跑窗口管理器。**
```bash
pkill -x openbox            # 杀掉 WM，让 IQmol 直接管理自己的窗口
```
代价是没有窗口装饰/拖拽，但录制完全不需要。

### 坑 2：无 WM 时 `windowactivate` 会静默失败

杀掉 openbox 后，`xdotool windowactivate` 报
`Your windowmanager claims not to support _NET_ACTIVE_WINDOW` 并放弃操作。
必须改用走 XSetInputFocus 的命令：

```bash
xdotool windowfocus "$MAIN"   # ✅ 无 WM 可用
xdotool windowactivate "$MAIN"  # ❌ 无 WM 报���
```

### 坑 3：不要用 `windowclose` 强杀 Qt::Popup

周期表是 `Qt::Popup`（`ToolBar.C: on_elementSelectButton_clicked`，位置跟随
`QCursor::pos()`）。用 `xdotool windowclose` 强关会破坏 Qt 内部的 popup 状态机，
之后**再也弹不出周期表**，且 `Escape` 无效。正确做法是点画布空白处让popup 自然关闭。

### 校准结论（无 WM 下的实测坐标）

| 目标 | 屏幕坐标 | 说明 |
|---|---|---|
| IQmol 主窗口 | `0,0` / 1920×1080 | `windowmove 0 0` + `windowsize 1920 1080` |
| 菜单栏 | y ≈ 34 | |
| 工具栏按钮带 | y ≈ 58（范围 46~70） | x 中心：27, 71, 115, …, 215, **266**, 310 … |
| 元素选择按钮（周期表） | **(262, 58)** | 已实测命中 |
| 元素周期表窗口 | 弹出后位于 `(9,33)`，514×263 | Qt::Popup，跟随光标 |

因为无 WM 时 **client 坐标 = 屏幕坐标**，不再有 openbox 的 22px 标题栏偏移，
这是坐标能一次对准的根本原因。

## 4. 校验门槛（防假英文 / 防假中文）

**唯一权威判据是启动日志，双向都要查**：

| 期望语言 | 必须出现的日志 |
|---|---|
| 中文 | `[i18n] Loaded translation: "zh_CN"` |
| 英文 | `No translation file found for: "en"` |

- 缺失 → 语言不对，必须重跑（先查 QSettings `Language` 键，再查 `zh_CN.qm` 是否就位）。
- **不要用画面判语言**：菜单栏像素比对和 OCR 在小字号下都不可靠（Qt 按钮宽度固定，中英宽度接近；
  逐项放大 OCR 也读不出）。本项目曾据此误判「录到了英文对照」，实际 4 次全是中文。
- 语言状态**跨会话残留**：QSettings 的 `Language` 键一写就一直生效，
  每次录完必须确认已删除，否则后续录制全部沿用上一次语言。
