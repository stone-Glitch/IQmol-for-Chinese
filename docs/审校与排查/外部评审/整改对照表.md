## 二、逐条详表（审查报告）

### P0-1 仓库体积失控（435 MB）

- **现状实证**：`submodules-package/` 5 个 tar.gz 仍直接入 git（IQmol-submodules 73 MB、openbabel-fix 32.6 MB、openbabel-formats-fix 1.3 MB、openbabel-deps 1.2 MB、data-headers 0.5 MB，合计 ≈108 MB）；历史残留误提交发行包（commit `493e1c7d`）。`submodules-package/SHA256SUMS.txt` 已建（前期任务），但文件本身仍在 git 跟踪内。
- **整改落点**：① 首选移出 git 作 Release 资产；② `git filter-repo --strip-blobs-bigger-than 10M` 清历史（需公告+强制推送）；③ 或 Git LFS（`.gitattributes`）。
- **难度**：高（重写历史需管理员权限、需公告与协作者重克隆）。建议放在下一个 Release 之前。

### P0-2 GeminalOrbitalsConfigurator 四个标签缺全角冒号

- **现状实证**：`translations/zh_CN.ts` 中 `GeminalOrbitalsConfigurator` 上下文的 4 条译文确认为 `类型`(3241)、`等值`(3246)、`不透明度`(3251)、`质量`(3256)——**全缺冒号**；而同类面板 `MolecularSurfacesConfigurator`/`OrbitalsConfigurator` 为 `类型：`/`等值面值：`/`不透明度：`/`质量：`（带冒号）。且 `Isovalue:` 应为"等值面值"而非"等值"。
- **整改落点**：`translations/zh_CN.ts` 4 条补冒号 + `Isovalue:`→`等值面值：` + 重新编译 `zh_CN.qm`。**纯翻译层、低风险、可逆**。
- **难度**：低。

### P1-3 版本口径三处不一致

- **现状实证**：`CHANGELOG.md` 最新条目为 `[3.2.3-zh_CN] - 2026-09-26`，`[Unreleased]` 为空，**无 3.2.4.1 条目**；`sbom.json` 第 11 行 `"version": "3.2.3-zh_CN"`；README 无版本号。`docs/构建与打包/release_notes.md` 已如实记录"实际最新 Release 为 v3.2.4.1-zh_CN、口径歧义"（前期任务）——即**口径歧义已记录，但 CHANGELOG 缺条目、sbom 版本号未同步**，未闭环。
- **整改落点**：补 `CHANGELOG.md` 的 `## [3.2.4.1-zh_CN] - 2026-10-03` 条目；同步 `sbom.json` 的 version/timestamp；加 CI 比对 release tag 与 sbom/CHANGELOG。
- **关联**：rFqwRF(SBOM) 之前标"已完成"指 THIRD_PARTY_LICENSES 在库，但 sbom.json 版本号细节未修，本次修订暴露该缺口。

### P1-4 术语不完全统一（12 处 + 附 2 处多译）

- **现状实证**：脚本对 `zh_CN.ts` 全量扫描，按 source 分组，**实证 14 组**同一原文多译（与报告 12 组吻合，另发现 `Alpha`/`To` 2 组，见附）。其中报告点名 12 组：

### P1-5 展示页截图在 GitHub 裂图

- **现状实证**：`docs/汉化成果速览.html` 用相对路径 `assets/ui/xxx.png`（20+ 张）；含 `view3d_viagra` 文件名（grep 命中 1 处）。

- **难度**：低。

### P1-6 GPL/LGPL 静态链接合规动作缺位

- **现状实证**：README「已知问题」已诚实提示合规风险；`THIRD_PARTY_LICENSES.md` 在库（rl48qr 已完成）。缺口：无 `RELINKING-NOTICE.md`、Release 未附 Qt LGPL 文本、未给重链接材料/书面要约。
- **整改落点**：补 `THIRD_PARTY_LICENSES.md` 一节或附 `Qt-LGPL-3.0.txt` + `RELINKING-NOTICE.md`（说明 Qt 版本/源码获取/重链方法）；最低成本改动态链接 Qt 随包附 DLL。
- **难度**：中（需懂开源合规复核）。

### P2-7 CI 工作流命名与幂等性

- **现状实证**：`.github/workflows/windows-msvc.yml` 存在（11 KB），实为 msys2/MinGW64，**文件名误导**；`ubuntu-2404.yml` 中 `sudo ln -s ...` 非幂等（已存在即 fail）。
- **整改落点**：① `git mv windows-msvc.yml windows-mingw.yml`；② `ln -s` 改 `ln -sfn` 或加 `[ -e ] ||`；③ 补 macOS CI + 文档改动 path filter。
- **难度**：低。

### P2-8 子模块离线包无版本漂移校验

- **现状实证**：CI 解 `submodules-package/*.tar.gz` 不走 `git submodule update`，无 MANIFEST 校验；`SHA256SUMS.txt` 已建但未做 gitlink sha 比对。
- **整改落点**：包内放 `MANIFEST.json`（path+commit sha+打包时间），CI 解包后比对 `.gitmodules` gitlink，不一致即 fail（约 30 行 shell）。
- **难度**：中。

### P2-9 翻译层"修拼写"改不掉的三处

- **现状实证**：`Lable6`(ts:10552) 在 `src/Viewer/ShaderDialog.ui:179`；`InChi`(ts:6020) 在 `src/Main/InsertMoleculeDialog.ui:46`；`mol2`(ts:11937) 源码侧未直接 grep 到（疑动态/别处）。`InChi`/`Lable6` 确为 .ui 显示字符串（经 tr 抽取），印证"真正要改的是源码大小写，翻译层改了下次 lupdate 仍会漂"。
- **整改落点**：objectName 类改源码；显示文案类统一源码大小写后重跑 lupdate。
- **难度**：低（定位后改源码）。

### P2-10 71 处硬编码英文残留，TQA 管不到源码侧

- **现状实证**：`docs/汉化工程/工程待办与现状登记.md` 已登记约 71 处硬编码（含 13 个电荷模型术语译法未定）；`i18n-tqa.yml` 门禁项全为"翻译文件侧"指标，无源码侧覆盖率。
- **整改落点**：`scripts/i18n/tqa.py` 增第 7 项——扫描 `src/` 中疑似用户可见字符串未 `tr()` 包裹的数量，设阈值（≤71 且不得增加），先卡恶化再清零。
- **关联**：#43 已排查但未清零。

### P3-11 可发现性几乎为零

- **现状实证**：0 star / 0 fork / 无 topics / 无 homepage / 无英文简介。
- **整改落点**：填 topics（iqmol、chemistry、molecular-visualization、qt5、chinese-localization、i18n、qchem、简体中文）；Homepage 填 iqmol.org；About 补英文一句；向 nutjunkie/IQmol3 上游反哺 tr()/踩坑发现。
- **难度**：低（需 GitHub 仓库设置权限）。

### P3-12 Release 无 SHA256SUMS 资产
