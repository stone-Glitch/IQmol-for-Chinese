### 2.2 第二层：真正未包 `tr()` 的字符串

排查中发现一处真实遗漏：

```
src/Qui/InputDialog.C:85    setWindowTitle("QChem Input File Editor - " + file.fileName());
src/Qui/InputDialog.C:489   setWindowTitle("QChem Input File Editor - " + file.fileName());
```

窗口标题**硬编码英文，未包 `tr()`** —— 这解释了截图标题栏的
`QChem Input File Editor - untitled.inp`。已记入待修清单。

### 2.3 第三层：context 可达性（本次排查的真正价值所在）

**这是一个常规检查完全测不到的故障类型。**

Qt 运行时按 context 查译文，而 context 由 `类名`（含命名空间）决定：

```cpp
tr("File")                              // 无命名空间的类 → context "Foo"
tr("File")  // 在 namespace Qui 的类内   → context "Qui::Foo"
```

若 `.ts` 里的 context 与运行时不一致，**译文存在但永远查不到**，界面保持英文。
此时以下检查**全部显示正常**：

| 检查 | 为什么测不出 |
|---|---|
| lupdate 提取 | 正常 —— 它确实提取到了 |
| TQA P1 源码漂移 | 0 —— 源码没变 |
| TQA P2 资产完整率 | 0 —— 条目都有译文 |
| TQA P3 QM 有效性 | 正常 —— `.qm` 里确实有这条 |

本项目的具体情形（已查清，**当前无缺陷**）：

| 来源 | lupdate 写入的 context | 说明 |
|---|---|---|
| `src/Qui/InputDialog.ui`（`<class>MainWindow</class>`） | `MainWindow` | uic 生成的代码用的就是它 ✅ |
| `src/Qui/InputDialog.C` | `InputDialog` | 实测运行时确实用不带 `Qui::` 的名字 ✅ |

两者**都能在运行时命中**，已由探针实测确认。

### 2.4 一个被推翻的误判

第一版排查脚本用「静态分析源码推断 context」（读文件里的 `namespace` + `class` 声明），
产出了 `Gmx::MainWindow`、`Layer::Molecule` 等大批「不可达」告警。

**这些是误报。** 实测显示 `IQmol::MainWindow` 是完好可达的。

误报根因：C++ 文件里 `namespace` 块的位置、前向声明、注释中的 namespace 字样
都会干扰静态推断；且**类定义在 `.h`、`tr()` 调用在 `.C`**，只看单文件必然误判。

> **教训**：context 可达性**不能靠静态推断**，必须以 `lupdate` 的输出为基准，
> 并用真实 `QTranslator` 实测验证。

## 三、新增工具

### 3.1 `scripts/i18n/context_reach.py`

两项能力：

```bash
# 基准比对：lupdate 需要什么 vs 仓库 .ts 有什么
python3 scripts/i18n/context_reach.py

# 运行时探针：用真实 QTranslator 查 .qm
python3 scripts/i18n/context_reach.py --probe translations/zh_CN.qm
```

### 3.2 `scripts/i18n/ctxprobe.C`

极小的 Qt 程序，直接用 `QTranslator::translate(context, source)` 查询并打印结果。
这是**运行时真相的唯一可靠来源** —— 任何静态分析都只是推断。

> 注：context 名本身含 `::`，因此探针参数分隔符用 `\t` 而非 `:`。

## 五、截图英文的可能来源

排除法后，剩余可能性按概率排序：

| 可能 | 说明 | 验证方法 |
|---|---|---|
| **1. 部署包中 `.qm` 缺失或位置错误** | 程序搜 `applicationDirPath()/translations/`；若包内没有该文件则回退英文 | 检查发布包内 `bin/translations/zh_CN.qm` 是否存在 |
| **2. 使用了旧构建** | `/tmp/iqmol_build` 是 9/19 的构建，含 `孪生` 等旧译法 | 比对构建时间与 `.qm` 内容 |
| **3. 截图来自英文原版** | 未加载翻译的运行 | 直接问用户 |
| **4. `Preferences::Language()` 被设为 `en`** | 用户手动切到英文 | 检查配置 |

这与 `reA22A`（`zh_CN.qm` 在 `translations/` 而非 `bin/translations/`）
**高度相关** —— 若打包脚本没有正确复制 `.qm`，就会出现截图的现象。

> **建议**：优先完成 `reA22A`。它是目前唯一能解释截图的、且已确认存在的具体缺陷。
