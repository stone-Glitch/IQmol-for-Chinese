# 审查补充材料技术订正说明

本文记录对「严格审查补充材料（57 测试用例 + 复现步骤）」中 **3 处技术事实错误** 的订正。
这些错误出现在补充材料文本中，与仓库实际代码/脚本状态不符；订正后不影响之前已通过的
测试用例结论。

## 订正 1：TC-P1-05 构建工具描述（MSVC / MinGW）

- **原文**：测试用例 TC-P1-05 描述 Windows 构建「使用 MSVC 或 MinGW」。
- **事实**：本仓库 Windows 构建链路（`scripts/build_windows.sh`、`.bat`、CMakeLists WIN32 分支）
  仅验证并支持 **MinGW-w64（GCC）** 工具链，配合 Qt5 的 MinGW 构建。**未提供、也未验证 MSVC 路径**
  （CMakeLists 中多处静态链接宏 `QGLVIEWER_STATIC` / `YAML_CPP_STATIC_DEFINE` / `STATIC_MAEPARSER` 等
  均针对 MinGW 静态语义）。
- **订正**：将 TC-P1-05 的构建工具限定为 **MinGW-w64**，删除「或 MSVC」表述；如需 MSVC 支持属新增工作项。

## 订正 2：`check_i18n.sh` 统计遗漏 numerus 消息

- **原文**：审查引用的 `check_i18n.sh` 用 `grep '<message>'` 统计未翻译条目。
- **事实**：Qt Linguist 对复数形式（numerus）消息生成 `<message numerus="yes">`，
  `grep '<message>'` **无法匹配** 该标签，导致复数翻译的 unfinished/缺失被漏统计。
- **订正**：统计脚本应改用 `xml.etree.ElementTree` 解析 `.ts`，
  同时覆盖 `<message>` 与 `<message numerus="yes">`，再判定 `type="unfinished"` 或空 `<translation>`。
  建议实现（节选）：
  ```python
  import xml.etree.ElementTree as ET
  root = ET.parse(ts_path).getroot()
  for msg in root.iter('message'):
      for tr in msg.findall('translation'):
          if tr.get('type') == 'unfinished' or (tr.text or '').strip() == '':
              unfinished += 1
  ```

## 订正 3：F-033 仓库构建标准描述（C++14 / 版本号）

- **原文**：审查子项 F-033 称「仓库 CMakeLists 仍停留在 C++14，且未同步上游版本号」。
- **事实**：当前 `main` 分支 `CMakeLists.txt` 实际为
  `set(CMAKE_CXX_STANDARD 17)`（第 9 行）且
  `project(${targetName} VERSION 3.2.3 ...)`（第 4 行），
  与上游 3.2.3 的 C++17 标准及版本号 **完全一致**。
- **订正**：F-033 关于「C++14 / 版本号未同步」的指控 **不成立**，予以撤回。
  （注：审查中另一子项 F-030「静默回退」同样不成立——CMakeLists 第 432 行已有
  `message(WARNING ...)` 显式提示缺失 lrelease 的后果。）

## 结论

上述 3 处均为补充材料文本的撰写偏差，仓库代码与构建脚本状态正确，无需改动源码；
仅需修正审查文档表述。相关待办 `rA0NzZ` 据此关闭。
