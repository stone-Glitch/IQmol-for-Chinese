# 无显卡环境下实机运行与录屏 IQmol

> 适用场景：CI 容器、云主机、沙箱等**没有物理显示器、没有 GPU** 的环境，
> 需要把 IQmol 真正跑起来看界面 / 截图 / 录演示视频。
> 验证日期：2026-10-02 ｜ 验证环境：Ubuntu 24.04 / 无 GPU / Mesa llvmpipe

> **文档分工**：本文是「怎么用」的操作指南（原理 + 步骤 + 六个坑）。其验证过程、实测数据与证据截图另见 [`验证记录/2026-10-02-无显卡虚拟窗口运行与录屏验证.md`](../验证记录/2026-10-02-无显卡虚拟窗口运行与录屏验证.md)——**二者互补、不合并**，请勿重复内容。

## 一、结论先行

**可行，且效果足以出推广视频。** 实测在纯 CPU 软件渲染下：

- IQmol 的 5 个 GLSL 着色器全部编译成功
- 球棍模型、蛋白二级结构渲染正常

## 二、技术栈原理

```
Xvfb                   提供虚拟 X 显示（无显示器也能有 DISPLAY）
  └─ Mesa llvmpipe     CPU 实现 OpenGL（无需 GPU，支持到 GL 4.5）
       └─ openbox       窗口管理器（关键！见第四节坑 1）
            └─ IQmol    真实二进制
                 └─ ffmpeg x11grab   抓取虚拟屏 → 视频
```

## 三、快速开始

### 3.1 依赖

```bash
sudo apt-get install -y \
  xvfb openbox xdotool imagemagick mesa-utils \
  qtbase5-dev libopenbabel-dev libqglviewer-dev-qt5 \
  cmake g++ gfortran
```

> `ffmpeg` 需带 `x11grab` 与 `libopenh264` 编码器；
> 项目环境已就位，可用 `scripts/video/setup_virtual_display.sh` 一键校验。

### 3.2 三步跑起来

```bash
# ① 校验依赖 + 生成 zh_CN locale
bash scripts/video/setup_virtual_display.sh

# ② 常驻启动显示与窗口管理器
#    ⚠️ 这两条各需放在**独立后台任务**里常驻，不能用普通 & 追加到脚本末尾
exec Xvfb :99 -screen 0 1920x1080x24 -nolisten tcp
DISPLAY=:99 openbox --sm-disable

# ③ 录屏（内部会自动构建检查、启动 IQmol、等中文加载、居中视图、录旋转）
bash scripts/video/record_virtual_display.sh \
  src/Parser/test/samples/viagra.xyz build-video/out/demo.mp4 16
```

### 3.3 手动跑（调试用）

```bash
export DISPLAY=:99
export LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe
export QT_QPA_PLATFORM=xcb QT_XCB_GL_INTEGRATION=xcb_glx
export LANG=zh_CN.UTF-8 LC_ALL=zh_CN.UTF-8 LANGUAGE=zh_CN

cd build-video && ./IQmol samples/../src/Parser/test/samples/viagra.xyz &
sleep 25
import -window root /tmp/shot.png        # 截一张
```

## 四、六个坑（全部踩过）

### 坑 1：没有窗口管理器 → 窗口尺寸不生效 ⭐ 最容易漏

**现象**：截图里 IQmol 只占屏幕左上角一小块，`xdotool windowsize 1920 1080`
执行后 `getwindowgeometry` 显示仍是 1920×1080，但**画面没变**。

**原因**：Xvfb 本身**没有窗口管理器**。Qt 发出的 resize 请求需要一个 WM 来落实
（reparent / configure）。没有 WM 时请求被丢弃，窗口保持创建时的尺寸。

**解法**：启动 `openbox`。验证：

```bash
pgrep -x openbox || (DISPLAY=:99 openbox --sm-disable &)
DISPLAY=:99 xdotool getwindowgeometry $(DISPLAY=:99 xdotool search --name "^IQmol$" | tail -1)
```

### 坑 2：误禁 GLX → Qt 建不出 GL 上下文

**现象**：`QXcbIntegration: Cannot create platform OpenGL context, neither GLX nor EGL are enabled`

**原因**：为了"省事"设了 `QT_XCB_GL_INTEGRATION=none`。

**解法**：**不要设这个变量**，或显式设为 `xcb_glx`。先确认 GLX 本身可用：

```bash
DISPLAY=:99 LIBGL_ALWAYS_SOFTWARE=1 glxinfo | grep "OpenGL renderer"
# 期望： llvmpipe (LLVM xx, 256 bits)
```

### 坑 3：后台进程被会话回收

**现象**：`Xvfb ... &` 之后立刻 `xdpyinfo` 还能用，过一会儿就 `unable to open display`。

**原因**：工具/CI 会话结束时，未脱离进程组的子进程会被一起清理。

**解法**：把 Xvfb 与 openbox 放到**独立的后台任务**里常驻
（WorkBuddy 中用 `run_in_background`；shell 中用 `setsid nohup ... &` 并确认
`pgrep` 能看到进程）。不要在同一个一次性脚本里 `&` 起它们就完事。

### 坑 4：zh_CN locale 未生成

**现象**：`warning: setlocale: LC_ALL: cannot change locale (zh_CN.UTF-8)`

**解法**：

```bash
sed -i 's/^# *zh_CN\.UTF-8 UTF-8/zh_CN.UTF-8 UTF-8/' /etc/locale.gen
locale-gen zh_CN.UTF-8
LC_ALL=zh_CN.UTF-8 date      # 期望输出「2026年 10月 02日 星期五」
```

### 坑 5：判断「中文是否生效」不要靠肉眼

界面看着是中文，也可能只是部分汉化或字体回退。
**认日志**（IQmol 启动时会打印）：

```bash
grep 'Loaded translation' build-video/out/logs/iqmol.log
# 期望： [i18n] Loaded translation: "zh_CN"
```

### 坑 6：全量编译会中途静默中断

**现象**：日志无 `error:`、无 OOM（内存充裕），突然停在某个 `.cpp`。

**原因**：沙箱会话回收把 `make` 带走了。

**解法**：直接重跑 `make`——CMake 会跳过已编译目标，从断点续上。
建议用**独立后台任务**跑，并加 `-j$(nproc)`。

## 七、性能提示

- **llvmpipe 是 CPU 渲染**：复杂分子旋转可能掉帧。大蛋白建议降低录制分辨率，
  或减小单帧旋转角度、拉长停留时间。
- **核数越多越流畅**：`nproc` 大于 16 时旋转明显更顺。
- **首次渲染慢**：载入分子后需等 8–20 秒（大 PDB 更久）再开始录制，
  避免录到"还在加载"的画面。脚本已默认等待 8 秒。
