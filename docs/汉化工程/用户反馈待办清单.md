## 二、双击文件打开的界面问题

| # | 反馈 | 状态 |
|---|---|---|
| F1 | **双击 `.fchk`（Windows）打开的界面部分未汉化** | ✅ **已修复**（2026-10-03，见下） |

### F1 诊断结论（详见 `缺陷诊断-fchk界面中英混杂.md`）

**实测方式**：Windows 包 + Wine 9.0 + Xvfb，`IQmol.exe water.fchk`，CWD 设为文件所在目录（模拟双击）。

**关键发现**：**翻译加载完全正常** —— 菜单栏「文件 编辑 显示 构建 计算 帮助」**全中文**。
用户看到的问题在**「历史记录」面板**：

```
Reperceive bonds     ← ★ 英文（未翻译）
新建分子              ← 中文
```

- **根因**：源码中该字符串**漏加 `tr()`**，从未进入翻译流程：

  ```cpp
  // src/Layer/MoleculeLayer.C:2439
  new Command::EditPrimitives("Reperceive bonds", this);   // ← 裸字符串，无 tr()
  ```

  `lupdate` 只提取 `tr()` 包裹的字符串 → `.ts` / `.qm` 中不存在该条目 →
  运行时 `QUndoCommand` 直接显示原文。**属代码缺陷，改 `.ts` 无法修复。**

- **二进制反证**：`IQmol.exe` 中 `zh_CN.qm` 含 `Reperceive Bonds`（大写 B），
  **不含** `Reperceive bonds`（小写 b）。Qt 翻译查找区分大小写，两者是不同条目。

- **全量扫描**：共发现 **8 处**同类缺陷，全部显示在「历史记录」面板：

  | 文件 : 行 | 裸字符串 |
  |---|---|
  | `MoleculeLayer.C:2439` | `Reperceive bonds` |
  | `MoleculeLayer.C:1548` | `Remove atoms/bonds` |
  | `ComponentLayer.C:114` | `Translate to center` |
  | `BuildEfpFragmentHandler.C:86` | `Add EFP fragment` |
  | `BuildMoleculeFragmentHandler.C:65` | `Add molecule` |
  | `UndoCommands.h:101,103` | `Move items` |
  | `UndoCommands.h:151` | `Add Charges` |
  | `UndoCommands.h:161,169` | `Minimize energy` / `Symmetrize structure` |

- **修复（已完成 2026-10-03）**：母仓库源码直接修复 **9 处**（精确写法见下），
  `lupdate` 抽取 8 条新条目 → 补中文译文 → `lrelease` 生成 `zh_CN.qm`（2120 条 / 0 unfinished）。
  同步并入 `patches/功能补丁-非机械改动.patch`（36→38 文件），确保上游迁移路径不再漏网。

  | 文件 : 行 | 裸字符串 | 修复写法 |
  |---|---|---|
  | `MoleculeLayer.C:1559` | `Remove atoms/bonds` | 裸 `tr()`（类有 Q_OBJECT） |
  | `MoleculeLayer.C:2450` | `Reperceive bonds` | 裸 `tr()` |
  | `MoleculeLayer.C:2193` | `Minimize energy` | 由调用点传 `tr()`（原在 `.h`） |
  | `MoleculeLayer.C:2279` | `Symmetrize structure` | 由调用点传 `tr()`（原在 `.h`） |
  | `ComponentLayer.C:114` | `Translate to center` | 裸 `tr()` |
  | `BuildEfpFragmentHandler.C:88` | `Add EFP fragment` | `QCoreApplication::translate()` |
  | `BuildMoleculeFragmentHandler.C:67` | `Add molecule` | `QCoreApplication::translate()` |
  | `UndoCommands.h`（MoveObjects 默认文本） | `Move items` | 兜底下沉到 `UndoCommands.C` 构造 |
  | `UndoCommands.h`（AddCharges，**暂无调用点**） | `Add Charges` | 接口参数化，未进 `.ts`（无调用=不显示） |

> ⚠️ **技术要求（易踩）**：`QUndoCommand` / `Handler::Base` 均**非 QObject**，不能裸用 `tr()`；
> 且 `lupdate` **不扫描 `.h`**，写在头文件的字面量永远抽不进士林表——这正是原草稿补丁被标
> "不要应用"的技术原因（它的 `tr()` 写法编译不过，且即便编译过译文也不生效）。

> ⚠️ **更正**：此前基于 Linux 包得出的"翻译路径候选缺失"结论**不适用于本场景**——
> Windows 包二进制中已含 `/../translations` 候选，路径无问题。
> 本问题与"文件关联/CWD"无关，纯粹是源码漏翻。
