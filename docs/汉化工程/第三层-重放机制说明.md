# 第三层：tr() 包裹重放机制说明

**定位**：[`docs/改动面最小化方案（第三层）.md`](改动面最小化方案（第三层）.md) 中 **A 项**的实现与验收记录。
**目标**：上游升级后，汉化成果中占比最大的 `tr()` 包裹可**脚本一键重建**，不必人工逐行核对。

---

## 一、为什么需要它

我们相对上游 `af7ff60` 改了 **42 个源码文件**，其中：

| 类别 | 文件数 | 性质 | 能否脚本重放 |
|---|---|---|---|
| `tr()` / `QCoreApplication::translate()` 包裹 | **36** | 机械改动（172 处） | ✅ 规则表 100% 覆盖 |
| 功能补丁（语言加载 / 偏好项 / GCC15 兼容） | **6** | 有语义的功能代码 | ⚠️ 需按补丁清单单独重放 |
| **合计** | **42** | | |

第一类占比最大，却也是上游改动时最容易冲突/丢失的部分。

原先的 `scripts/i18n/wrap_tr.py` 是**行号驱动**的一次性脚本：

```python
# 现状：硬编码行号，只为 MainWindow.C 服务
FILE = "/workspace/IQmol3/src/Main/MainWindow.C"
NAME_LINES = { 368: '"About"', 372: '"New Molecule"', ... }   # 行号 = 上游改动即失效
```

行号是**上游代码的一个时间切片**。上游在 `MainWindow.C` 前面加一行，所有行号集体
偏移，脚本全废，且 `assert expected in line` 会直接抛错。更关键的是它只覆盖 1 个文件，
而我们有 36 个。

---

## 二、机制

### 2.1 规则表（内容驱动）

`scripts/i18n/wrap_tr.rules`，TSV 格式：

```
<相对路径>\t<字面量>\t<形态>\t<出现次数>
```

| 形态 | 含义 | 重放结果 |
|---|---|---|
| `call:<函数名>` | 字面量是某个调用的参数 | `<函数名>(tr("字面量"))` |
| `bare` | 字面量在赋值/三元/流操作等位置 | `tr("字面量")` |
| `translate:<上下文>` | 非 QObject 类没有 `tr()` | `QCoreApplication::translate("<上下文>", "字面量")` |

示例：

```
src/Configurator/NmrConfigurator.C	Resolution	call:m_ui->widthLabel->setText	1
src/Main/MainWindow.C	About	bare	1
src/Viewer/UndoCommands.C	Add constraint	translate:UndoCommands	1
```

### 2.2 关键设计一：形态 + 出现次数共同约束重放范围

同名字面量在同一文件里可能出现在不同上下文，而只包裹其中一部分：

```cpp
m_spectrum->yAxis->setLabel(tr("Rel. Strength"));   // 第 341 行：包裹
m_spectrum->yAxis->setLabel("Rel. Strength");       // 第 345 行：不包裹
```

规则记 `count=1`，重放时只包第一处。

### 2.3 关键设计二：同一字面量可有多种形态（三元组键）

```cpp
// MainWindow.C 里的 Save 同时以两种形态出现
messageBox.addButton(tr("Save"), QMessageBox::AcceptRole)   // call:messageBox.addButton
name = tr("Save");                                           // bare
```

规则表键是 **`(路径, 字面量, 形态)` 三元组**，因此这两处各占一行，都能被覆盖。
（早期用 `(路径, 字面量)` 二元组时漏掉了其中一种，已修正。）

### 2.4 关键设计三：count 的语义 = "最终包裹总数"（语义 B）

```python
# ExcitedStatesConfigurator.C 中
第 341 行  setLabel(tr("Rel. Strength"))   ← 上游已自带
第 345 行  setLabel("Rel. Strength")       ← 裸的，由我们包裹
```

若按"diff 新增行的包裹数"计数（语义 A）会得到 `count=1`，重放到成果上时判定
"还有 1 处未包" → 再包一次 → **不幂等**。因此 count 取"该字面量在成果文件中
最终被包裹的总数"（语义 B），重放时补 `count - 已包裹数` 处。

### 2.5 关键设计四：补足式 vs 构造式

| 形态 | 上游原文 | 重放动作 |
|---|---|---|
| `call:` / `bare` | 上游往往已有部分 `tr()` | **补足**：找裸字面量，补上 `tr(...)` |
| `translate:` | 上游是**裸字面量**，从无 `translate()` | **构造**：连 `QCoreApplication::translate("Ctx", ...)` 一起生成 |

`translate:` 形态额外会自动注入 `#include <QCoreApplication>`（若原文件没有）。
这是 `UndoCommands.C` 独有的形态（`QUndoCommand` 不是 QObject，没有 `tr()`）。

### 2.6 三个工具

| 脚本 | 职责 |
|---|---|
| `extract_tr_rules.py` | 从 `git diff <base>..HEAD` **反向提取**规则表；`--verify` 校验覆盖率 |
| `replay_tr.py` | 按规则表**幂等重放**；默认 dry-run，`--apply` 才落盘 |
| `wrap_tr.rules` | 内容驱动的规则表（自动生成，勿手改） |

幂等性：已包裹为 `tr("X")` / `translate("Ctx", "X")` 的不会被二次包裹，
因此重复执行结果稳定。

## 三、验收（关键数据）

在**上游基线工作区**（`git worktree add /tmp/replaytest af7ff60`）上重放，再与成果逐文件比对：

| 指标 | 结果 |
|---|---|
| 规则条数 | **250**（覆盖 36 个文件） |
| `diff` 中 tr()/translate() 处数 | **172** |
| 被规则覆盖 | **172 / 172 = 100%** |
| 重放后与成果**完全一致**的文件 | **29 / 36** |
| 剩余 6 个文件 | 差异性质为**语义级重构**，规则表无法表达（见下节） |
| 幂等性 | ✅ 二次重放 0 改动（基线 + 成果两侧均验证） |
| 上游基线重放改动量 | 160 处 / 33 个文件 |

> 也就是说：**29 个文件的翻译包裹可在上游任意版本上一键精确重建**，
> 剩下的 6 个文件需要人工过一眼（但差异点已明确定位到个位数行）。

## 四、已知例外（6 个文件，需人工核对）

### 4.1 拼接 → 占位符重构（5 个）

基线用字符串拼接，成果改写为 Qt 占位符，**目的是让翻译系统能处理变量插值**：

```cpp
// 基线
setText("Angle between atoms " + atoms);
// 成果
setText(tr("Angle between atoms %1").arg(atoms));
```

| 文件 | 残余差异行数 | 说明 |
|---|---|---|
| `src/Configurator/ConstraintConfigurator.C` | 6 | |
| `src/Configurator/SurfaceAnimatorDialog.C` | 6 | |
| `src/Layer/GeminalOrbitalsLayer.C` | 4 | |
| `src/Configurator/MullikenDecompositionsDialog.C` | 2 | |
| `src/Qui/GeometryConstraint.C` | 2 | 跨行拼接 |

> `src/Viewer/UndoCommands.C` 原先也在此列（残余 21 行），自 `translate:` 形态
> 支持后已降至 **1 行**（仅剩 `"Load file " + fileName()` 一处拼接重构），
> 与上表同类。故本类实际为 6 个文件，其中 UndoCommands 已基本可重放。

### 4.2 常量 → 可翻译字面量替换（1 个）

```cpp
// 基线
Molecule::Molecule(QObject* parent) : Component(DefaultMoleculeName, parent),
// 成果
Molecule::Molecule(QObject* parent) : Component(tr("Untitled"), parent),
```

`src/Layer/MoleculeLayer.C`（残余差异 4 行）。`DefaultMoleculeName` 是宏/常量，
改成字面量才能被 `lupdate` 提取，属语义级改动。

### 4.3 功能补丁清单（6 个文件，不含翻译包裹）

这 6 个文件相对上游有改动，但**一行 `tr()` 都没有**，因此规则表天然覆盖不到。
它们需要按下面的清单在上游升级后重新应用：

| 文件 | 改动 | 目的 |
|---|---|---|
| `src/Main/IQmolApplication.C` | +69 行 | `loadTranslations()`：加载 Qt 基础翻译 + 应用翻译，三态语言偏好 |
| `src/Main/IQmolApplication.h` | +4 行 | 上述方法的声明与 `QTranslator*` 成员 |
| `src/Main/PreferencesBrowser.C` | +12 行 | 语言下拉框（中文/English/跟随系统）的读写绑定 |
| `src/Util/Preferences.C` | +21 行 | `Language()` 偏好存取（哨兵值 `"system"`） |
| `src/Util/Preferences.h` | +5 行 | 上述函数声明 |
| `src/Layer/OctreeLayer.C` | +1 行 | `#include <cstdint>`（GCC 15+ 需显式包含） |

> 这几处是**功能性**改动，语言逻辑集中于 `IQmolApplication::loadTranslations()`，
> 属于第三层 **C 项（语言逻辑收敛）** 的既有成果，改动面已经很小。

### 4.4 一个已修正的陷阱（存档）

品牌名 `IQmol` 在不同上下文里处理**不一致**：

```cpp
setWindowTitle(tr("IQmol"));                          // 包裹（窗口标题参与翻译）
QMessageBox(..., "IQmol", tr("Save Changes?"));       // 不包裹（消息框署名不翻）
QMsgBox::information(this, "IQmol", tr("..."));       // 不包裹
```

初版 `replay_tr.py` 用全局排除名单把 `IQmol` 一律跳过，导致 `setWindowTitle`
那一处漏包。**正确做法是尊重规则表的 `call:` 上下文**，而非一刀切排除。
该陷阱已修复并记录在脚本注释中。

## 五、上游升级后怎么用

```bash
# 1. 合并上游
bash scripts/sync_upstream.sh --merge

# 2. 看本次升级导致哪些翻译包裹丢失（dry-run，先审阅，不落盘）
python3 scripts/i18n/replay_tr.py

# 3. 确认无误后重放
python3 scripts/i18n/replay_tr.py --apply

# 4. 复核差异
git diff --stat

# 5. （可选）重新提取规则表，吸收后续新增的包裹
python3 scripts/i18n/extract_tr_rules.py --base <新基线> --verify

# 6. 按 §4.3 清单重新应用 6 个功能补丁（若上游改动了这些文件）

# 7. 构建验证
bash scripts/build_windows.sh
```

## 六、收益

| 项 | 改造前 | 改造后 |
|---|---|---|
| 恢复翻译包裹 | 人工逐行核对 36 个文件 | 一条命令，29 个文件精确重建 |
| 规则载体 | 硬编码行号（1 个文件） | 内容驱动规则表（36 个文件 / 250 条） |
| 上游改动后可用性 | 行号偏移即全废 | 规则可跨版本复用 |
| 覆盖的翻译形态 | 仅 `tr()` | `tr()` + `QCoreApplication::translate()` |
| 幂等性 | 无（重复执行会二次包裹） | 有（两侧验证 0 改动） |
| 需人工核对的残余 | 7 个文件（未定性） | 6 个文件（差异已定位到 2~6 行） |
