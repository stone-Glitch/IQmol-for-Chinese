# 构建与部署指南

本文档说明如何从源码编译出**中文界面**的 IQmol，覆盖 Windows / Linux / macOS 三个平台，
包含离线包准备、构建、部署、验证与常见失败排查。

> 仓库地址：<https://github.com/stone-Glitch/IQmol-for-Chinese>
> 汉化成果：界面 **2112 条**翻译全部完成（`translations/zh_CN.ts`，153 个 context，0 未译）、
> 中文用户手册 34 页（`doc/IQmolUserGuide.pdf`）。

> 本文合并了原 `doc/构建说明-中文版.md`、`doc/编译-照着敲.md` 与
> `docs/验证记录/README.md` 的「如何复现验证」章节，是构建相关内容的**唯一权威来源**。
> 历史诊断记录见 [`../验证记录/`](../验证记录/)。

## 一、三条铁律（先读，能省几小时）

| 铁律 | 原因 |
|---|---|
| **CMake 必须用 3.27~3.31，禁用 4.x** | 子模块（HighFive / OpenBabel / OpenMesh / yaml-cpp）声明的 `cmake_minimum_required` 低于 3.5，且 OpenBabel 用 `cmake_policy(SET CMP0042 OLD)`。CMake 4.0 起移除了对 < 3.5 的兼容并禁止 CMP0042 设 OLD，configure 阶段必崩。MSYS2 自带的 `mingw-w64-x86_64-cmake` 目前是 4.x，须绕开（脚本会自动下载 portable 3.31） |
| **必须用 MINGW64 终端的 `tar` 解压 `.tar.gz`** | 360 压缩 / 7-Zip / WinRAR 图形界面解压会**静默丢文件**（本项目已连续两轮因此缺文件：先缺 `libinchi`/`test`，再缺 `formats/xml`、`formats/json`），且常只解出中间层 `.tar` |
| **仓库放短英文路径**（如 `D:\iqmol`） | Windows 有 260 字符路径上限，子模块目录层级很深，中文长路径会导致解压失败 |

## 二、获取源码与离线包

### 2.1 克隆仓库

IQmol3 依赖 9 个第三方库（Git 子模块），克隆时用 `--recursive`：

```bash
git clone --recursive https://github.com/stone-Glitch/IQmol-for-Chinese.git
```

或用仓库自带脚本：`scripts/clone_repo.sh`（Linux/macOS/Git Bash）、`scripts/clone_repo.ps1`（Windows）。

### 2.2 子模块拉不动时用离线包（国内网络建议直接走这条路）

子模块共约 470 MB，国内常卡在 `Failed to connect to github.com:443`。先只克隆主仓库
（不带 `--recursive`），再下载离线包。

**四包解压顺序（顺序错了会白干）：**

| 包 | 大小 | 包内顶层 | 解压位置 |
|---|---|---|---|
| `IQmol-submodules.tar.gz` | 73 MB（49,335 个文件） | `modules/` | **源码根** |
| `IQmol-openbabel-deps.tar.gz` | 1.2 MB | `external/` | `modules/openbabel/` |
| `IQmol-openbabel-fix.tar.gz` | 32 MB | `modules/openbabel/` | **源码根** |
| `IQmol-openbabel-formats-fix.tar.gz` | 1.3 MB | `modules/openbabel/` | **源码根** |

```bash
cd /d/IQmol/IQmol-src
tar -xzf ../IQmol-submodules.tar.gz                        # → modules/
tar -xzf ../IQmol-openbabel-deps.tar.gz -C modules/openbabel  # → external/
tar -xzf ../IQmol-openbabel-fix.tar.gz                     # 在源码根解压
tar -xzf ../IQmol-openbabel-formats-fix.tar.gz             # 在源码根解压
```

> ⚠️ **顺序陷阱**：重新解压 `IQmol-submodules.tar.gz` 会把 `openbabel/CMakeLists.txt`
> 覆盖回**未修版**，uninstall 重名冲突会原样复现（174 行冲突）。必须是
> **先完整包 → 再打两个 fix 包**。`build_windows.sh` 也会自动检测并修复该冲突。
>
> ⚠️ Windows 用户可直接运行 `extract_submodules.bat "D:\iqmol"`（校验大小+MD5 后自动解压）。
>
> ⚠️ 解压后**不要再执行 `git submodule update`**，否则会重新联网克隆、覆盖刚解压的文件。

**各包的作用：**

- `deps`：OpenBabel 的 3 个构建期依赖（maeparser / coordgenlibs / rapidjson）。不解压也能编，
  但 CMake 会在构建 OpenBabel 时联网拉取，国内必失败（`FATAL_ERROR: Failed getting or unpacking ...`）。
- `fix`：补全 `libinchi/`、`test/` 目录，并给 `ADD_CUSTOM_TARGET(uninstall)` 加重名保护
  （与 yaml-cpp 的 uninstall 目标冲突，CMP0002）。
- `formats-fix`：补全 `src/formats/` 下 128 个格式源文件（xml / json 等）。

缺失时的报错分别是：`add_subdirectory ... not an existing directory`、
`No SOURCES given to target: pubchem / xmlformat / cmlreactformat / ...`、
`uninstall ... target with the same name already exists`。

### 2.3 解压完整性自检（9 条命令都应输出路径）

```bash
cd /d/IQmol/IQmol-src
ls -1 modules/CMakeLists.txt
ls -1 modules/openbabel/src/formats/xml/pubchem.cpp
ls -1 modules/openbabel/src/formats/json/chemdoodlejsonformat.cpp
ls -1 modules/openbabel/src/formats/json/pubchemjsonformat.cpp
ls -1 modules/openbabel/external/maeparser-v1.2.3/README.md
ls -1 modules/openbabel/external/coordgen-master/README.md
ls -1 modules/openbabel/external/rapidjson-1.1.0/readme.md
ls -1 modules/openbabel/src/formats/libinchi/ichidrp.h
ls -1 modules/openbabel/test/CMakeLists.txt
```

任何一条报 `No such file or directory`，说明包不完整或解压顺序错了，先回去重解压。

## 三、Windows 构建（产出 IQmol.exe）

### 3.1 安装依赖

**方式 A：一键脚本（推荐，装到 D 盘）**

右键 `scripts/安装依赖.bat` → 以管理员身份运行。脚本会自动下载 MSYS2 自解压归档 →
解压到 `D:\msys64` → 更新系统 → 安装 gcc/cmake/Qt5/Boost/OpenSSL/zlib/HDF5。
完成后双击 `D:\msys64\mingw64.exe` 进入 MINGW64 终端。想换盘符就改脚本顶部 `MSYS2_ROOT`。

**方式 B：手动安装**

从 <https://www.msys2.org/> 安装，打开 **MSYS2 MINGW64** 终端（必须是 MINGW64，不是 MSYS）；
从 <https://cmake.org/download/> 取 **portable CMake 3.31**（zip 免安装），把 `bin/` 放到 PATH 最前。

```bash
pacman -Syu   # 首次更新系统，可能要求重启终端，之后重新进入 MINGW64
pacman -S --needed \
  mingw-w64-x86_64-gcc \
  mingw-w64-x86_64-cmake \
  mingw-w64-x86_64-make \
  mingw-w64-x86_64-qt5-base \
  mingw-w64-x86_64-qt5-tools \
  mingw-w64-x86_64-boost \
  mingw-w64-x86_64-openssl \
  mingw-w64-x86_64-zlib \
  mingw-w64-x86_64-hdf5
```

> `qt5-tools` 提供 `lrelease`（中文本地化）与 `windeployqt`（打包运行库），务必安装。

### 3.2 一键构建（推荐）

```bash
cd IQmol-for-Chinese
bash ./scripts/build_windows.sh
```

脚本会依次：补全缺失的 `modules/CMakeLists.txt` → 检测并修复 openbabel 的 uninstall 冲突 →
检测 CMake 4.x 并自动下载 portable 3.31 到 `.tools/` → **配置指纹自检**（比对
`BUILD_SHARED` 同步、`--whole-archive`，变化则自动重新 configure）→ configure → 编译 →
生成 `zh_CN.qm`。运行前还会自检 CMake 版本、子模块是否解压、OpenBabel 三个 external
依赖是否就位、仓库路径是否过长。

| 命令 | 作用 |
|---|---|
| `bash ./scripts/build_windows.sh` | 增量编译（日常推荐） |
| `bash ./scripts/build_windows.sh --clean` | 删 `build/` 从零 configure（慢） |
| `JOBS=8 bash ./scripts/build_windows.sh` | 强制 8 线程 |
| `CMAKE_BIN="D:/cmake-3.31/bin/cmake.exe" bash ./scripts/build_windows.sh` | 指定已有 CMake 3.31 |

**若坚持用 cmd**：`scripts\build_windows.bat`（需自行把 CMake 3.31 的 `bin/` 放到 PATH 最前）。

**增量行为**：`build/` 已有 `CMakeCache.txt` 且关键配置未变时跳过 configure 直接编译；
编译中断后重跑会续编剩余的 `.o`；检测到关键配置变化会自动重新 configure。
**除非要换 CMake 参数，否则不要删 `build/`**。

### 3.3 手动构建（适合排查问题）

```bash
cd /d/IQmol/IQmol-src
cmake31="D:/IQmol/IQmol-src/.tools/cmake-3.31.6/bin/cmake.exe"
"$cmake31" --version            # 应显示 3.31.x

mkdir -p build && cd build
"$cmake31" .. \
  -G "MinGW Makefiles" \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="/d/msys64/mingw64" \
  -DCMAKE_CXX_FLAGS="-fpermissive -std=gnu++17 -Wno-deprecated" \
  -DCMAKE_MAKE_PROGRAM="mingw32-make" \
  -DBOOST_ROOT="/d/msys64/mingw64" 2>&1 | tee config.log

mingw32-make -j4 2>&1 | tee make.log
```

configure 成功会生成 `build/CMakeCache.txt`，之后直接进去 `mingw32-make -j4` 即可，不要重跑 `cmake ..`。

### 3.4 编译省时的三条铁律

1. **首次 configure 慢是正常的**（1~5 分钟），它要编译大量小程序做特性检测；保留 `build/` 就不会再花这个时间。
2. **不要习惯性 `rm -rf build/`**——这是最容易踩的坑。
3. **并行度 `-j4` 到 `-j8` 为宜**。开满（`-j32`）容易因单编译单元 1~2 GB 峰值内存而 OOM，反而更慢。

## 四、Linux 构建

```bash
sudo apt-get install build-essential cmake qtbase5-dev qt5-qmake \
  libqt5opengl5-dev libboost-all-dev libssl-dev zlib1g-dev \
  libopenbabel-dev libeigen3-dev libarchive-dev libyaml-cpp-dev \
  libssh2-1-dev libhdf5-dev libxml2-dev

cd IQmol-for-Chinese
./configure --release          # 生成 build/ 目录
cd build
make -j
```

产物 `build/IQmol`，中文 `.qm` 随构建自动生成到可执行文件同级 `translations/`。

> 需要 `qttools5-dev-tools`（提供 `lrelease`/`lupdate`）才会生成翻译，否则界面回退英文。

## 五、macOS 构建

```bash
brew install qt@5 boost openbabel libarchive yaml-cpp libssh2 hdf5 libxml2

cd IQmol-for-Chinese
./configure --release
cd build
make -j
```

产物 `build/bin/IQmol.app`（上游 CMake 已配置 macOS 打包）。

## 六、产物与部署

### 6.1 产物

| 平台 | 可执行文件 | 中文翻译 |
|---|---|---|
| Windows | `build/bin/IQmol.exe`（注意在 `bin/` 子目录） | `build/bin/translations/zh_CN.qm` |
| Linux | `build/IQmol` | 同级 `translations/zh_CN.qm` |
| macOS | `build/bin/IQmol.app` | 随 bundle 生成 |

### 6.2 Windows：必须执行一次部署

Windows 版**不能直接双击运行**，需先复制 Qt 插件、MinGW 运行库与资源：

```bash
bash ./scripts/deploy_windows.sh                 # 就地部署
bash ./scripts/deploy_windows.sh --stage D:\dist  # 整理成 D:\dist\IQmol\{bin,share,lib}
```

脚本依次处理：

| 步骤 | 内容 |
|---|---|
| 1 | `windeployqt` 复制 Qt DLL 与平台插件（缺失时回退手工复制） |
| 2 | 同步 Qt 插件到 `lib/plugins/`（对齐源码 `addLibraryPath`） |
| 3 | 复制 MinGW 运行库（`libstdc++-6.dll` 等） |
| 4 | 复制 IQmol 资源 `share/`（着色器、片段库等） |
| 5 | 复制 OpenBabel 数据到 `share/openbabel/`（扁平 + 版本子目录双份） |
| 6 | 复制精选示例分子到 `samples/`（单文件 ≤ 1 MB） |
| 7 | 确认 `bin/translations/zh_CN.qm` 就位（缺失则现场 `lrelease`） |
| 8 | 自检力场参数文件（`UFF.prm` / `ghemical.prm` / `gaff.prm` / `mm2.prm`） |

**目录约定**（源码 `src/Main/IQmolApplication.C`，Windows 下运行时根 = 可执行文件上一级）：

| 用途 | 路径 |
|---|---|
| Qt 插件 | `<根>/lib/plugins` |
| OpenBabel 数据 | `<根>/share/openbabel` |
| 着色器 / 片段库 | `<根>/share/shaders`、`share/fragments` |
| 示例分子 | `<根>/samples` |
| 中文翻译 | `<可执行文件同级>/translations/zh_CN.qm` |

> 不要手动跑 `windeployqt` 代替部署脚本——`deploy_windows.sh` 还处理 MinGW 运行库、
> `share/` 资源与 OpenBabel 数据。

### 6.3 Linux：一键分发包

```bash
bash scripts/package_linux.sh --build <构建目录>    # 默认 <源码根>/build
# 产出 dist/IQmol-linux-x86_64.tar.gz
tar xzf IQmol-linux-x86_64.tar.gz && ./IQmol-linux-x86_64/run.sh
```

包内自带 Qt 运行库与插件、OpenBabel 数据与运行期插件、`share/` 资源、精选示例分子、
以及两处 `zh_CN.qm`（包根 `translations/` 与 `bin/translations/` 双保险，修复旧包
「仅从包根启动才加载中文」的缺陷）。详见 [`Linux分发包.md`](Linux分发包.md)。

着色器（Cel / Gooch / Gouraud / Phong / Plastic）编译通过。

## 九、常见失败排查

### 9.1 configure 阶段

| 现象 | 原因 / 处理 |
|---|---|
| `cmake: command not found` | 未在 MINGW64 终端操作，或未装 `mingw-w64-x86_64-cmake` |
| `CMake < 3.5 has been removed` / `CMP0042` 相关错误 | 用了 CMake 4.x，改用 portable 3.31 并前置 PATH（脚本会自动下载） |
| `add_subdirectory given source modules/zstd ... does not contain CMakeLists.txt` | 旧版 `CMakeLists.txt`，`git pull` 拿到修正版（已去掉不存在的 zstd 引用） |
| `add_subdirectory given source "libinchi"/"test" ... not an existing directory` | 未解压 `IQmol-openbabel-fix.tar.gz` |
| `ADD_CUSTOM_TARGET cannot create target "uninstall" ... already exists` | fix 包未覆盖 `modules/openbabel/CMakeLists.txt`，按 2.2 顺序重解压 |
| `No SOURCES given to target: pubchem / xmlformat / ...` | 未解压 formats-fix 包，或解压丢文件 |
| OpenBabel 报 `Failed getting or unpacking Maeparser/Coordgen/RapidJSON` | 未解压 `IQmol-openbabel-deps.tar.gz` |
| `babelconfig.h: No such file or directory` | 源码不是最新 master（补丁已在仓库里） |

### 9.2 编译 / 链接阶段

| 现象 | 原因 / 处理 |
|---|---|
| `undefined reference to __imp__ZN9QGLViewer...` / `__imp__ZN4YAML...` | QGLViewer / yaml-cpp 是静态库但头文件按 DLL 导入展开；需 `QGLVIEWER_STATIC YAML_CPP_STATIC_DEFINE`（已修） |
| `undefined reference to __imp_glStencil*` / `gluNewQuadric` | OpenGL / GLU 未链接（CMake 3.14+ 不再设 `OPENGL_LIBRARIES`）；需 `OPENGL_TARGET` / `GLU_TARGET` 收敛（已修） |
| OpenBabel 静态链接报 maeparser / `additional_sources` 相关 undefined reference | 静态分支漏加 `additional_sources`、maeparser 宏名应为 `STATIC_MAEPARSER`（已修），详见 [`../验证记录/OpenBabel构建故障排查.md`](../验证记录/OpenBabel构建故障排查.md) |
| `No rule to make target 'modules/openbabel/src/libopenbabel.a'` | `--whole-archive` 误用 `$<TARGET_FILE:...>` 破坏依赖跟踪；应用目标名 `openbabel` + `add_dependencies`（已修） |
| 找不到 Qt5 | 未装 `mingw-w64-x86_64-qt5-base`，或未在 MINGW64 环境执行 |
| 编译一半报错，第二次重跑又好了 | MinGW 文件锁 / 并行问题；`mingw32-make -j1` 或重跑脚本 |
| 改了 `CMakeLists.txt` 但行为没变 | 构建未重新 configure；重跑脚本（有配置指纹自检），见 [`../验证记录/构建与补丁问题排查.md`](../验证记录/构建与补丁问题排查.md) |

### 9.3 运行阶段

| 现象 | 原因 / 处理 |
|---|---|
| `Unable to find OpenBabel plugins` | OpenBabel `BUILD_SHARED` 未与顶层同步，插件未内联；需 `set(BUILD_SHARED OFF CACHE ... FORCE)`（已修） |
| `Failed to load force field: UFF` | 静态库中插件自注册对象被链接器丢弃；需 `--whole-archive` 包裹（已修） |
| `windeployqt: command not found` | 安装 `mingw-w64-x86_64-qt5-tools` |
| 界面仍是英文 | 缺 `bin/translations/zh_CN.qm`（`qt5-tools` 未装导致 `lrelease` 缺失），装好后重跑部署 |
| Linux 分发包界面是英文 | 旧包缺陷（reA22A），新版已双处放置 qm 并补 `../translations` 搜索路径；见 [`../验证记录/翻译与仓库核查.md`](../验证记录/翻译与仓库核查.md) |

> **排查心法**：很多报错的**提示文案本身具有误导性**。例如 `Failed to load force field`
> 提示「BABEL_DATADIR 可能没设对」，实际原因通常是构建配置（见 9.2/9.3）。
> 遇到「环境变量/路径」类提示时，先确认构建配置是否真的生效，再查运行环境。

## 十、求助时请提供

1. 执行的**完整命令**；
2. configure 或编译输出中**第一条** `error:`（或 `CMake Error`）前后 10 行；
3. `build/CMakeCache.txt` 的前 20 行（确认 CMake 版本与生成器）；
4. 若脚本报错，附 `build_run.log` 的头部 + 关键行 + 尾部：

```bash
bash ./scripts/build_windows.sh 2>&1 | tee build_run.log
head -30 build_run.log
grep -nE "ERROR|error:|CMake Error|Built target" build_run.log | tail -30
tail -40 build_run.log
```
