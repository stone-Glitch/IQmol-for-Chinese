# 下载源码后直接打包（零补丁）

**适用对象**：想从源码构建 / 打包 IQmol 中文版的人（Windows 或 Linux）。
**一句话结论**：当前 `main` 分支源码**已是完整汉化成果版**，**无需 apply 任何补丁**，下载后直接三步出包。

> `patches/` 目录里的两个 `.patch` 仅用于「上游升级迁移」（见 [`../../patches/README.md`](../../patches/README.md)），对打包者无意义，可忽略。误 `git apply` 会因改动已合入源码树而失败。

---

## 一、获取源码

**方式 A · git clone（网络正常）**

```bash
git clone https://github.com/stone-Glitch/IQmol-for-Chinese.git
cd IQmol-for-Chinese
```

**方式 B · 下载源码包（弱网推荐）**

从发布页下载 `IQmol-src-<commit>.zip`，解压到本地，例如得到 `D:\IQmol\IQmol3`。
源码包已内含 Windows 构建必需的 `submodules-package/`（离线依赖），无需另拉子模块分支。

---

## 二、Windows 打包（MSYS2 / MinGW64）

前提：已安装 MSYS2 并配好 Qt5 等构建依赖（详见 `scripts/build_windows.sh` 头部说明）。

```bash
cd IQmol3
bash scripts/build_windows.sh
bash scripts/deploy_windows.sh --stage dist
bash scripts/package_windows.sh --zip
```

产物：`dist/IQmol-win...zip`（Windows 原生中文版，开箱即用）。

---

## 三、Linux 打包

前提：已安装 Qt5 开发包、cmake、OpenBabel（详见 `scripts/package_linux.sh` 头部说明）。

```bash
mkdir build && cd build
cmake .. && make -j$(nproc)
cd ..
bash scripts/package_linux.sh --build build
```

产物：`dist/IQmol-linux-x86_64.tar.gz`（含 `run.sh`，执行 `./run.sh` 启动中文版）。

---

## 四、验证（可选）

Linux 包内置端到端自检：

```bash
bash scripts/verify_linux_pkg.sh
```

预期：`通过 16 项，失败 0 项`（覆盖：翻译任意工作目录加载、OpenBabel 包内自包含、示例分子加载 + 力场计算）。

---

## 五、常见问题

- **Q：要不要先 `git apply patches/*.patch`？**
  A：**不要。** 当前源码已含全部汉化改动（语言支持、tr() 包裹、QChem 库汉化等），apply 会因已合入而失败。
- **Q：缺 `samples/` 或 `submodules-package/`？**
  A：源码包已包含；git 方式请确保完整 clone（含 `submodules-package/`），这是 Windows 离线构建的依赖。
- **Q：构建报缺依赖？**
  A：先读对应 `scripts/build_windows.sh` 或 `scripts/package_linux.sh` 头部的依赖清单，把 Qt5 / OpenBabel / 编译器等装齐再构建。
