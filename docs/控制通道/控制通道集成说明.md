# IQmol 本地控制通道

给 IQmol 加一条**只在本机可达**的控制通道，让外部程序（例如 `dsh-chem-viz`
插件的 Node 层）能够查询状态、加载分子文件，而不用模拟鼠标。

白名单里的 **13 个命令全部已接真实接口**（`ping` / `load` / `state` /
`snapshot` / `play` / `pause` / `stop` / `frame` / `surface` / `listSurfaces` /
`clear` / `render` / `movie`），冒烟脚本 **31/31 通过**。唯一的例外是
`surface` 只支持三种无需外部格点数据的伪密度面（见「已知限制」）。

---

## 一、组成

| 文件 | 作用 |
|---|---|
| `src/Main/ControlServer.h` / `.C` | 协议层：Unix domain socket、token 鉴权、命令白名单、帧缓冲 |
| `src/Main/IQmolApplication.C` | 命令实现：`startControlServer()` + `onControlCommand()` |
| `src/Main/MainWindow.h` | 新增 `viewerModel()` / `viewer()` 只读访问器 |
| `scripts/iqmol_control_smoke.py` | 冒烟测试客户端 |

`ControlServer` 只负责「解析帧、校验 token、查白名单、发信号」，完全不懂分子；
所有真正的动作在 `IQmolApplication` 里。这样补丁对 IQmol 的侵入面只有一处信号连接。

## 二、启动与发现

控制通道在 `IQmolApplication` 构造末尾自动启动。启动失败（例如另一个实例已占用
socket）**只写日志，绝不影响 IQmol 正常使用**。

关闭方式：

```bash
IQMOL_NO_CONTROL=1 iqmol
```

启动后会在运行时目录写一个发现文件：

```bash
cat "${XDG_RUNTIME_DIR:-/tmp}/iqmol-ctrl.json"
```

```json
{
  "v": 1,
  "pid": 19814,
  "endpoint": "/tmp/iqmol-ctrl.sock",
  "token": "741be5a1-...",
  "startedAt": "2026-11-07T08:59:36Z",
  "commands": ["ping", "load", "state", "play", "..."]
}
```

> 上面是**未设 `XDG_RUNTIME_DIR`** 的容器 / root 环境示例，目录为 `/tmp`；
> 正常桌面会话下为 `/run/user/<uid>`。旧文档曾写 `/tmp/runtime-root`，那是
> Qt `RuntimeLocation` 的回退值，已按第二节的说明修正，不要再照抄。

文件权限 `0600`，只有本用户可读。**token 是唯一凭据**，非本用户进程读不到它。

### 发现路径：两端必须落在同一个目录

这一条是实际联调时踩到的坑，部署前务必确认。

客户端的候选列表（`lib/iqmol-ctl.js::endpointCandidates()`）是：

1. `$XDG_RUNTIME_DIR/iqmol-ctrl.json`
2. `$TMPDIR` / `/tmp/iqmol-ctrl.json`
3. `~/.iqmol/iqmol-ctrl.json`

如果 `ControlServer` 直接用 `QStandardPaths::RuntimeLocation`，在**没有**
`XDG_RUNTIME_DIR` 的环境（容器、root、无登录会话）Qt 会回退到
`/tmp/runtime-<user>`，而 Node 的 `os.tmpdir()` 回退到 `/tmp` —— 两端永远
找不到彼此。实测就是这样：`probe()` 返回 `no-endpoint-file`，而 IQmol 明明
在跑。

所以 `ControlServer::runtimeDir()` 改成：

- `XDG_RUNTIME_DIR` 已设 → 直接用它（正常桌面：`/run/user/1000`，两端一致）；
- 未设 → 用 `QStandardPaths::TempLocation`（即 `/tmp`），与 `os.tmpdir()` 对齐。

两种情形都已验证：`probe()` 均返回 `alive: true`。

## 三、协议

一行一个 JSON，请求与响应靠 `id` 配对。

请求：

```json
{"v":1,"id":"a1","token":"<token>","cmd":"ping","args":{}}
```

成功：

```json
{"v":1,"id":"a1","ok":true,"result":{"pong":true}}
```

失败：

```json
{"v":1,"id":"a1","ok":false,"error":{"code":"LOAD_FAILED","message":"..."}}
```

错误码：`BAD_JSON`、`BAD_VERSION`、`BAD_COMMAND`、`BAD_ARGS`、`LOAD_FAILED`、
`NOT_READY`、`BUSY`、`NOT_IMPLEMENTED`。

**token 不对时服务端不回任何内容，直接断开连接** —— 未授权的本地进程连
「这里有个 IQmol」都探不到。

### 命令

#### `ping`

```json
{"pong": true}
```

#### `state`

```json
{
  "pid": 19814,
  "version": "v3.2.4.1-zh_CN",
  "packageVersion": "3.2.4.1",
  "tag": "v3.2.4.1-zh_CN-45-gXXXXXXX",
  "startedAt": "2026-11-07T08:59:36Z",
  "commands": ["frame", "listSurfaces", "load", "pause", "ping", "play",
               "snapshot", "state", "stop", "surface"],
  "scene": {"molecules": 7, "surfaces": 2, "tracks": 1, "animating": false}
}
```

`version` / `tag` 由 CMake 在配置时用 `git describe` 生成（无 `.git` 时退回包版本），
`packageVersion` 取自 CMake `PROJECT_VERSION`，与 `dpkg -s iqmol` / 压缩包名一致。
从此不再依赖长期停滞的 `src/version.h`，「关于」对话框、日志、控制通道三处版本一致。
`commands` 已排序，可直接做集合断言。`id` 原样回显，整数/字符串都可配对。

`scene.molecules` 是当前 ViewerModel 里的分子层数量。IQmol 启动时会自带一个
空白 viewer，所以初始值是 `1`，不是 `0`。

#### `load`

```json
{"path": "/abs/path/3nir.pdb"}
```

```json
{"loaded": true, "path": "/abs/path/3nir.pdb", "molecules": 5}
```

`ViewerModel::open()` 在后台任务里解析，命令会**等到 `fileOpened` 信号或 20 秒
超时**再回复，所以客户端拿到 `loaded:true` 就代表分子已经在场景里了。

传 `"replace": true` 会先调用 `clear` 再加载，响应里带 `replaced` 与 `cleared`。
这解决了 IQmol 原生「追加 System 并隐藏前一个」导致的连续加载后视图空白问题；
实测连续两次 `replace` 加载同一文件，分子数保持 `1 -> 1`。

#### `snapshot`

把当前三维视图渲染成图片，只允许写进固定目录（默认
`$TMPDIR/iqmol-snapshots/`）。`out` 只当**文件名**用，任何路径成分都会被丢弃：

```json
{"out": "scene.png", "width": 1280, "height": 800}
```

```json
{"path": "/tmp/iqmol-snapshots/scene.png", "width": 1280, "height": 800, "bytes": 216337}
```

- 尺寸夹在 64–4096 之间，缺省 `1200x900`，96 DPI、4x 抗锯齿；非数字直接 `BAD_ARGS`；
- `out` 取 `basename` 后必须匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,59}\.(png|jpg)$`，
  不匹配先尝试补 `.png`，仍不匹配返回 `BAD_ARGS`（所以 `-rf.png`、超长名都会被拒）；
- `out` 传 `../../etc/x.png` 只会得到 `/tmp/iqmol-snapshots/x.png`；
- 渲染失败（无 GL 上下文或产出 0 字节）返回 `SNAPSHOT_FAILED`。

> 实测：同一场景重复渲染字节完全一致（确定性），与窗口截图观感相同。曾观察到
> 一次性灰色带状伪影，进程内重启后不再复现，疑为首次离屏渲染的 llvmpipe 状态，
> 尚未定位，真机 GPU 未验证。

#### `play` / `pause` / `stop`

无参数。IQmol **没有全局 `animator()`**：动画器由 `Layer::Frequencies` /
`Layer::GeometryList` 通过 `ViewerModel::pushAnimators` 推入
`Viewer::m_animatorList`。所以这三个命令驱动的是层，而不是某个 viewer 方法：

```json
{"playing": true, "animations": 2, "timer": true}
```

- `play` 调 `setPlay(true)`，层自己 `pushAnimators()` 启动 QGLViewer 定时器；
- `pause` 调 `setPlay(false)` 并**显式** `stopAnimation()`——只要还有别的动画器，
  QGLViewer 不会自己停表；
- `stop` 额外 `clearActiveMode()` / `resetGeometry()` 并停表；
- 空场景返回 `animations: 0` 加 `hint`，不报错；
- 带 `"track": n` 时只驱动第 n 条 `GeometryList`，不动频率层与其它轨迹，
  响应带 `singleTrack: true` / `track`；越界或非整数返回 `BAD_ARGS`。

#### `frame`

`frame {}` 是**只读查询**，返回场景里每条几何轨迹的帧数：

```json
{"tracks": [14, 17, 2], "count": 3}
```

带 `n` 时切帧，可用 `track` 选择第几条轨迹（默认 0）：

```json
{"n": 7, "track": 0}
```
```json
{"tracks": [14, 17, 2], "count": 3, "track": 0,
 "frame": 7, "frames": 14, "requested": 7}
```

索引超出范围会**钳制**并带 `clamped: true`；`track` 越界或非整数返回
`BAD_ARGS`。帧数取 `GeometryList::rowCount()`，与 `setCurrentGeometry()` 的
索引空间一致。实测 `fsm.out` 14 帧，切到第 0/7 帧后两次 `snapshot` 的
MD5 不同，证明画面确实变了。

#### `listSurfaces`

遍历整棵场景树里的 `Layer::Surface`，返回中文显示名、稳定的英文数据键、
可见性、面积、是否带符号/属性数据：

```json
{"count": 2, "surfaces": [
  {"name": "范德华", "key": "van der Waals", "visible": true,
   "area": 137.55, "signed": false, "hasProperty": false}
]}
```

原上游的 `area()` / `isSigned()` 是 `protected`，为此加了三个只读访问器；
`ViewerModel::findLayers` 是 `private`，加了显式的 `controlFindLayers` 转发。

#### `surface`

生成一张伪密度面，同步返回新的表面清单：

```json
{"type": "vdw", "quality": 1, "iso": 1.0}
```

`type` 只接受 `vdw` / `promolecule` / `sid`——这三种走
`MolecularSurfaces::calculateVanDerWaals()` / `calculateSuperposition()`，
不需要外部格点数据。为此给 `Layer::MolecularSurfaces` 加了
`requestSurface()` 入口，把 GUI 里「排队 → 等配置对话框 accepted」两步合成一步。
`quality` 夹在 0–5，`iso` 默认 0.02。轨道/电子密度面需要
`Grid::Evaluator` 与 cube 数据，传 `orbital` 会返回 `BAD_ARGS`。

#### `clear`

清空当前场景，无参数：

```json
{"cleared": 2, "molecules": 0}
```

> 注意 IQmol 的场景树把 `Layer::Molecule` 直接挂在根节点下，通常**没有**
> `Layer::System` 节点，所以这里遍历 `moleculeList(false)` 并逐个调用
> `removeMolecule()`（GUI 删除分子用的同一条 `Command::RemoveMolecule`），
> 而不是 `removeSystem()`。

#### `render`

沿指定几何轨迹逐帧切帧并保存 PNG 序列，输出固定在
`$TMPDIR/iqmol-renders/<prefix>/`：

```json
{"prefix": "traj", "track": 0, "from": 0, "to": 2, "width": 800, "height": 600}
```

```json
{"prefix": "traj", "track": 0, "from": 0, "to": 2, "count": 3,
 "width": 800, "height": 600, "dir": "/tmp/iqmol-renders/traj",
 "frames": [{"frame": 0, "index": 0, "file": ".../traj_0000.png", "bytes": 5812}]}
```

- `prefix` 只取 basename 且必须匹配 `^[A-Za-z0-9][A-Za-z0-9_-]{0,39}$`；
- `from` / `to` 钳制到轨迹范围并自动交换逆序，单次最多 300 帧；
- 每帧走与 `snapshot` 相同的 `Viewer::saveImage(path, QSize, 96, 4)`，
  帧间 `processEvents(ExcludeUserInputEvents)` 让画面刷新；
- 渲染期间置 `m_controlBusy`，防止第二个请求插进来；结束后把轨迹复位到
  `from`。无轨迹返回 `NO_FRAMES`，渲染失败返回 `RENDER_FAILED`。

#### `movie`

参数与 `render` 相同，额外支持 `fps`（1–60，缺省 12）。先渲染序列，再用
`QProcess` 调 ffmpeg 合成 `<prefix>.mp4`：

```json
{"movie": "/tmp/iqmol-renders/traj/traj.mp4", "bytes": 6553,
 "fps": 6, "codec": "mpeg4"}
```

编码器优先 `libx264`，检测到精简版 ffmpeg 缺该编码器时**自动回退 `mpeg4`**
（同为 mp4 容器），响应里的 `codec` 说明实际使用哪个。两者都失败返回
`MOVIE_FAILED` 并带回 ffmpeg 的 stderr。

## 四、与 `dsh-chem-viz/iqmol-patch/INTEGRATION.md` 的差异

原说明书有几处是「按上游推断、未核对」的，实测下来都要改：

| 原说明假设 | 实际情况 | 本仓库的处理 |
|---|---|---|
| `IQmolApplication::openFile(path)` | 不存在。入口是 `MainWindow::open(QString)`，无返回值 | 改为「找 MainWindow → `mw->open(path)` → 等 `ViewerModel::fileOpened`」 |
| 同步返回成功与否 | `ViewerModel::open()` 是**异步**的（`ParseJobFiles` 任务） | 用 `QEventLoop` 等信号，20 秒超时 |
| `Viewer` 有 `currentNumberOfFrames()` / `animator()` / `grabFrame()` / `addSurface()` | 均不存在。动画器由各 Layer 推入 `Viewer::m_animatorList`，帧在 `GeometryList` 子行，抓帧是 `saveImage` | 按真实结构适配：`play/pause/stop` 驱动 Layer，`frame` 用 `setCurrentGeometry()`，`snapshot` 用 `saveImage()`，`surface` 用 `MolecularSurfaces` |
| `id` 为字符串 | 协议未规定类型，Node 客户端常用整数；原实现用 `toString()` 会回成空串 | 改为保留 `QJsonValue` 原类型回显，整数/字符串都能配对 |
| Qt 组件含 `Network` | 原 `find_package` 只有 Core/Gui/Xml/PrintSupport/Widgets/OpenGL/Sql | 根 `CMakeLists.txt` 与 `src/Main/CMakeLists.txt` 都加了 `Network` |
| `src/CMakeLists.txt` 显式列源文件 | 上游是分层 `add_subdirectory`，`Main` 层用显式 `SOURCES` 列表 | 在 `src/Main/CMakeLists.txt` 的 `HEADERS`/`SOURCES` 各加一行 |
| `startedAt` 未暴露 | — | 给 `ControlServer` 加了 `startedAt()` |
| `QJsonArray` 可用 | 原 `ControlServer.C` 漏了 `#include <QJsonArray>` | 已补 |
| `QCoreApplication::applicationVersion()` | IQmol 没调用 `setApplicationVersion()`，返回空串 | 改用 CMake 编译期注入的 `IQMOL_VERSION_STR` / `IQMOL_GIT_VERSION` |
| `QStandardPaths::RuntimeLocation` 作发现目录 | 无 `XDG_RUNTIME_DIR` 时落到 `/tmp/runtime-<user>`，与 Node 的 `/tmp` 不一致 | 改为优先 `XDG_RUNTIME_DIR`，否则用 `/tmp`（见上节） |

## 五、已知限制

1. **`load` 默认是追加语义**，每次调用都会新建一个 viewer。需要替换场景
   时用 `clear`，或直接给 `load` 传 `"replace": true`（已实测幂等）。
   这是 IQmol 原生行为，与用户手动「打开文件」一致。
2. **并发请求返回 `BUSY`，不排队。** `load` 期间会跑嵌套事件循环，此时到达的
   其他请求一律拒绝。20 并发压测：2 个成功、18 个 `BUSY`，进程无崩溃。
   客户端应串行调用。
3. **`load` 的 20 秒上限是硬编码的。** 超长文件（如上千帧的优化轨迹）可能超时，
   此时文件其实仍在后台解析，`state` 稍后能观察到分子数增加。
4. **`surface` 只支持三种伪密度面。** `orbital` / `density` 等需要格点或
   cube 数据，当前返回 `BAD_ARGS`。接入点是
   `Layer::CubeData::calculateSurface(Data::SurfaceInfo)`（public slot，内部走
   `MarchingCubes`），但要求场景里已有 cube 数据层且需把生成的 `Layer::Surface`
   挂回层树，属于另一条数据管线，本轮未打通。
   `play` 不带 `track` 时驱动场景里**所有**动画层，带 `track` 可单选；
   `frame` 的 `track` 仍需调用方自己指定。
5. **无头（offscreen）环境下 3D 视图无法渲染**（`QOpenGLWidget: Failed to
   create context`）。`load` / `state` 仍然正常，`snapshot` 必须有真实 GL
   上下文（虚拟显示或真机均可）。

### 用 dsh-chem-viz 的真实客户端联调

Python 脚本只能证明协议自洽，真正的验收是插件的 Node 客户端能连上。
用 `lib/iqmol-ctl.js` 直接调用（IQmol 无头运行中）：

```js
import { probe, send } from 'dsh-chem-viz/lib/iqmol-ctl.js'

await probe()                                   // { alive: true, reason: 'ok' }
await send('state')                             // { version: 'v3.2.4.1-zh_CN', packageVersion: '3.2.4.1', ... }
await send('load', { path: 'samples/3nir.pdb' })// { loaded: true, molecules: 5 }
await send('surface', { type: 'vdw' })          // { count: 2, surfaces: [...] }
await send('listSurfaces')                      // { count: 2, ... }
await send('frame', {})                         // { tracks: [...], count: n }
await send('snapshot', { out: 'x.png' })        // { path: '/tmp/iqmol-snapshots/x.png', bytes: ... }
```

实测全部符合预期。

## 七、下一步

13 个白名单命令已全部接通。本轮补齐了此前「下一步」里的前三项
（`clear` / `replace`、无头批量 `render` / `movie`、`play` 单选），
剩余工作按代价排序：

- **`surface` 的轨道/密度类型**：唯一还缺的能力。需要打通
  `Grid::Evaluator` + cube 数据加载，并把 `Layer::CubeData::calculateSurface()`
  生成的表面挂回层树；GUI 路径由 `CubeDataConfigurator` 驱动，控制通道需提供
  等价的同步入口。接入点已定位，本轮未实现。
- **真机 GPU 复核**：llvmpipe 下曾出现一次性灰色带状伪影，重启后不复现；
  真机 GPU 未验证。
- **macOS / Windows 通道验证**：控制通道的 `QLocalServer` 在 Windows 走
  named pipe，本轮冒烟只在 Linux/Xvfb 上跑过。

批量渲染仍要求真实 GL 上下文（Xvfb 或真机），offscreen 下拿不到图。
