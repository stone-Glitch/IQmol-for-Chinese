# IQmol 本地控制通道

给 IQmol 加一条**只在本机可达**的控制通道，让外部程序（例如 `dsh-chem-viz`
插件的 Node 层）能够查询状态、加载分子文件，而不用模拟鼠标。

当前实现覆盖 `ping` / `load` / `state` / `snapshot`，已在本仓库实测通过。
动画与表面控制（`play` / `pause` / `stop` / `frame` / `surface` / `listSurfaces`）
只做了命令白名单，处理函数返回 `NOT_IMPLEMENTED`。

---

## 一、组成

| 文件 | 作用 |
|---|---|
| `src/Main/ControlServer.h` / `.C` | 协议层：Unix domain socket、token 鉴权、命令白名单、帧缓冲 |
| `src/Main/IQmolApplication.C` | 命令实现：`startControlServer()` + `onControlCommand()` |
| `src/Main/MainWindow.h` | 新增 `viewerModel()` / `viewer()` 只读访问器 |
| `scripts/iqmol_control_smoke.py` | 冒烟测试客户端 |

`ControlServer` 只负责「解析帧、校验 token、查白名单、发信号」，完全不懂分子；
所有真正的动作在 `IQmolApplication` 里。这样补丁对 IQmol 的侵入面只有一处信号连接。

---

## 二、启动与发现

控制通道在 `IQmolApplication` 构造末尾自动启动。启动失败（例如另一个实例已占用
socket）**只写日志，绝不影响 IQmol 正常使用**。

关闭方式：

```bash
IQMOL_NO_CONTROL=1 iqmol
```

启动后会在运行时目录写一个发现文件：

```bash
cat "${XDG_RUNTIME_DIR:-/tmp/runtime-root}/iqmol-ctrl.json"
```

```json
{
  "v": 1,
  "pid": 19814,
  "endpoint": "/tmp/runtime-root/iqmol-ctrl.sock",
  "token": "741be5a1-...",
  "startedAt": "2026-11-07T08:59:36Z",
  "commands": ["ping", "load", "state", "play", "..."]
}
```

文件权限 `0600`，只有本用户可读。**token 是唯一凭据**，非本用户进程读不到它。

### 发现路径：两端必须落在同一个目录

这一条是实际联调时踩到的坑，部署前务必确认。

客户端的候选列表（`lib/iqmol-ctl.js::endpointCandidates()`）是：

1. `$XDG_RUNTIME_DIR/iqmol-ctrl.json`
2. `$TMPDIR` / `/tmp/iqmol-ctrl.json`
3. `~/.iqmol/iqmol-ctrl.json`

如果 `ControlServer` 直接用 `QStandardPaths::RuntimeLocation`，在**没有**
`XDG_RUNTIME_DIR` 的环境（容器、root、无登录会话）Qt 会回退到
`/tmp/runtime-<user>`，而 Node 的 `os.tmpdir()` 回退到 `/tmp` —— 两端永远
找不到彼此。实测就是这样：`probe()` 返回 `no-endpoint-file`，而 IQmol 明明
在跑。

所以 `ControlServer::runtimeDir()` 改成：

- `XDG_RUNTIME_DIR` 已设 → 直接用它（正常桌面：`/run/user/1000`，两端一致）；
- 未设 → 用 `QStandardPaths::TempLocation`（即 `/tmp`），与 `os.tmpdir()` 对齐。

两种情形都已验证：`probe()` 均返回 `alive: true`。

## 三、协议

一行一个 JSON，请求与响应靠 `id` 配对。

请求：

```json
{"v":1,"id":"a1","token":"<token>","cmd":"ping","args":{}}
```

成功：

```json
{"v":1,"id":"a1","ok":true,"result":{"pong":true}}
```

失败：

```json
{"v":1,"id":"a1","ok":false,"error":{"code":"LOAD_FAILED","message":"..."}}
```

错误码：`BAD_JSON`、`BAD_VERSION`、`BAD_COMMAND`、`BAD_ARGS`、`LOAD_FAILED`、
`NOT_READY`、`BUSY`、`NOT_IMPLEMENTED`。

**token 不对时服务端不回任何内容，直接断开连接** —— 未授权的本地进程连
「这里有个 IQmol」都探不到。

### 命令

#### `ping`

```json
{"pong": true}
```

#### `state`

```json
{
  "pid": 19814,
  "version": "v3.2.3",
  "packageVersion": "3.2.4.1",
  "tag": "v3.2.2-1-g485ddc6",
  "startedAt": "2026-11-07T08:59:36Z",
  "commands": ["frame", "listSurfaces", "load", "pause", "ping", "play",
               "snapshot", "state", "stop", "surface"],
  "scene": {"molecules": 7}
}
```

`version` / `tag` 由 CMake 在配置时用 `git describe` 生成（无 `.git` 时退回包版本），
`packageVersion` 取自 CMake `PROJECT_VERSION`，与 `dpkg -s iqmol` / 压缩包名一致。
从此不再依赖长期停滞的 `src/version.h`，「关于」对话框、日志、控制通道三处版本一致。
`commands` 已排序，可直接做集合断言。`id` 原样回显，整数/字符串都可配对。

`scene.molecules` 是当前 ViewerModel 里的分子层数量。IQmol 启动时会自带一个
空白 viewer，所以初始值是 `1`，不是 `0`。

#### `load`

```json
{"path": "/abs/path/3nir.pdb"}
```

```json
{"loaded": true, "path": "/abs/path/3nir.pdb", "molecules": 5}
```

`ViewerModel::open()` 在后台任务里解析，命令会**等到 `fileOpened` 信号或 20 秒
超时**再回复，所以客户端拿到 `loaded:true` 就代表分子已经在场景里了。

#### `snapshot`

把当前三维视图渲染成图片，只允许写进固定目录（默认
`$TMPDIR/iqmol-snapshots/`）。`out` 只当**文件名**用，任何路径成分都会被丢弃：

```json
{"out": "scene.png", "width": 1280, "height": 800}
```

```json
{"path": "/tmp/iqmol-snapshots/scene.png", "width": 1280, "height": 800, "bytes": 216337}
```

- 尺寸夹在 64–4096 之间，缺省 `1200x900`，96 DPI、4x 抗锯齿；非数字直接 `BAD_ARGS`；
- `out` 取 `basename` 后必须匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,59}\.(png|jpg)$`，
  不匹配先尝试补 `.png`，仍不匹配返回 `BAD_ARGS`（所以 `-rf.png`、超长名都会被拒）；
- `out` 传 `../../etc/x.png` 只会得到 `/tmp/iqmol-snapshots/x.png`；
- 渲染失败（无 GL 上下文或产出 0 字节）返回 `SNAPSHOT_FAILED`。

> 实测：同一场景重复渲染字节完全一致（确定性），与窗口截图观感相同。曾观察到
> 一次性灰色带状伪影，进程内重启后不再复现，疑为首次离屏渲染的 llvmpipe 状态，
> 尚未定位，真机 GPU 未验证。

## 四、与 `dsh-chem-viz/iqmol-patch/INTEGRATION.md` 的差异

原说明书有几处是「按上游推断、未核对」的，实测下来都要改：

| 原说明假设 | 实际情况 | 本仓库的处理 |
|---|---|---|
| `IQmolApplication::openFile(path)` | 不存在。入口是 `MainWindow::open(QString)`，无返回值 | 改为「找 MainWindow → `mw->open(path)` → 等 `ViewerModel::fileOpened`」 |
| 同步返回成功与否 | `ViewerModel::open()` 是**异步**的（`ParseJobFiles` 任务） | 用 `QEventLoop` 等信号，20 秒超时 |
| `Viewer` 有 `currentNumberOfFrames()` / `animator()` / `grabFrame()` / `addSurface()` | 均不存在（帧管理在 `AnimatorList`，抓帧是 `saveImage` / `takeSnapshot`） | `snapshot` 改走 `Viewer::saveImage()` 并已实现；动画/表面命令仍返回 `NOT_IMPLEMENTED` |
| `id` 为字符串 | 协议未规定类型，Node 客户端常用整数；原实现用 `toString()` 会回成空串 | 改为保留 `QJsonValue` 原类型回显，整数/字符串都能配对 |
| Qt 组件含 `Network` | 原 `find_package` 只有 Core/Gui/Xml/PrintSupport/Widgets/OpenGL/Sql | 根 `CMakeLists.txt` 与 `src/Main/CMakeLists.txt` 都加了 `Network` |
| `src/CMakeLists.txt` 显式列源文件 | 上游是分层 `add_subdirectory`，`Main` 层用显式 `SOURCES` 列表 | 在 `src/Main/CMakeLists.txt` 的 `HEADERS`/`SOURCES` 各加一行 |
| `startedAt` 未暴露 | — | 给 `ControlServer` 加了 `startedAt()` |
| `QJsonArray` 可用 | 原 `ControlServer.C` 漏了 `#include <QJsonArray>` | 已补 |
| `QCoreApplication::applicationVersion()` | IQmol 没调用 `setApplicationVersion()`，返回空串 | 改用 `version.h` 的 `IQMOL_VERSION` / `GIT_VERSION` |
| `QStandardPaths::RuntimeLocation` 作发现目录 | 无 `XDG_RUNTIME_DIR` 时落到 `/tmp/runtime-<user>`，与 Node 的 `/tmp` 不一致 | 改为优先 `XDG_RUNTIME_DIR`，否则用 `/tmp`（见上节） |

## 五、已知限制

1. **`load` 是追加语义。** 每次调用都会新建一个 viewer，不会替换当前场景。
   实测：连续两次 `load 3nir.pdb`，分子数 7 → 11 → 15。这是 IQmol 原生行为
   （和用户手动「打开文件」一致），调用方应自行保证只加载一次。
2. **并发请求返回 `BUSY`，不排队。** `load` 期间会跑嵌套事件循环，此时到达的
   其他请求一律拒绝。20 并发压测：2 个成功、18 个 `BUSY`，进程无崩溃。
   客户端应串行调用。
3. **`load` 的 20 秒上限是硬编码的。** 超长文件（如上千帧的优化轨迹）可能超时，
   此时文件其实仍在后台解析，`state` 稍后能观察到分子数增加。
4. **动画与表面控制未接。** `play` / `pause` / `stop` / `frame` / `surface` /
   `listSurfaces` 在白名单里，但返回 `NOT_IMPLEMENTED`。`snapshot` 已实现。
5. **无头（offscreen）环境下 3D 视图无法渲染**（`QOpenGLWidget: Failed to
   create context`）。`load` / `state` 仍然正常，`snapshot` 必须有真实 GL
   上下文（虚拟显示或真机均可）。

```bash

import json, socket
info = json.load(open('/tmp/iqmol-ctrl.json'))
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM); s.settimeout(90)
s.connect(info['endpoint']); f = s.makefile()
s.sendall((json.dumps({"v":1,"id":1,"token":info["token"],
                       "cmd":"snapshot","args":{"out":"scene.png","width":1280,"height":800}})+"\n").encode())
print(f.readline())
PY
```

### 用 dsh-chem-viz 的真实客户端联调

Python 脚本只能证明协议自洽，真正的验收是插件的 Node 客户端能连上。
用 `lib/iqmol-ctl.js` 直接调用（IQmol 无头运行中）：

```js
import { probe, send } from 'dsh-chem-viz/lib/iqmol-ctl.js'

await probe()                                   // { alive: true, reason: 'ok' }
await send('state')                             // { version: 'v3.2.3', packageVersion: '3.2.4.1', ... }
await send('load', { path: 'samples/3nir.pdb' })// { loaded: true, molecules: 5 }
await send('snapshot', { out: 'x.png' })        // { path: '/tmp/iqmol-snapshots/x.png', bytes: ... }
```

实测全部符合预期。

## 七、下一步

`snapshot` 已完成。剩下的视图控制需要在 `Viewer` / `AnimatorList` /
`SurfaceLayer` 上重新设计适配层，而不是照抄原说明书的 `m_viewer->animator()`。
最低要做：

- 取当前活动 viewer 的 `AnimatorList`，从中拿到帧数与当前帧；
- `play/pause/stop` 映射到 `Animator` 已有的方法；
- `surface` 复用 `SurfaceLayer` 的添加逻辑，需要先构造 `Data::Surface`；
- `listSurfaces` 遍历活动分子的 `SurfaceLayer` 子层。

每一项都要在真实 GL 环境（有显示或软件渲染）里验证。
