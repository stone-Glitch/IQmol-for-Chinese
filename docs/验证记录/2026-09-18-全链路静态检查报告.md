## 二、发现并修复的问题：语言切换"跟随系统"是假的

### 现象
issue4 新增的「界面语言」下拉中，**「跟随系统」与「中文」行为完全相同**——
即使系统是英文，选「跟随系统」仍强制显示中文。

### 根因
`Preferences::Language()` 用**空字符串**表示"跟随系统"，但 `loadTranslations()`
无法区分"用户显式选了跟随系统"与"从未设置过"（首次运行）：

```cpp
// 旧逻辑
QString pref = Preferences::Language();
if (!pref.isEmpty()) {
   locale = pref;
} else if (!locale.startsWith("zh")) {
   locale = "zh_CN";        // ← 首次运行与"跟随系统"都落这里 → 都变中文
}
```

### 修复
引入显式哨兵值 `"system"` 区分三态，并新增第四个隐含态（未设置=首次运行）：

| 取值 | 含义 | 行为 |
|---|---|---|
| `"system"` | 显式跟随系统 | 用系统 locale，无翻译文件则回退英文 |
| `"zh_CN"` | 强制中文 | 加载 zh_CN |
| `"en"` | English | 加载 en（通常无文件→英文） |
| 未设置 | 首次运行 | 保持汉化默认（非中文环境也显示中文） |

改动文件：
- `src/Util/Preferences.C`：`Language()` 注释与语义说明
- `src/Util/Preferences.h`：注释同步
- `src/Main/IQmolApplication.C`：`loadTranslations()` 四态判断
- `src/Main/PreferencesBrowser.C`：下拉读写映射（`"system"` 而非空串）

### 验证
用 C++ 单元测试复刻决策逻辑，8 个场景全部通过：

```
PASS pref=''       sys=en_US -> zh_CN   （首次运行+英文系统=汉化默认中文）
PASS pref=''       sys=zh_CN -> zh_CN
PASS pref='en'     sys=zh_CN -> en
PASS pref='en'     sys=en_US -> en
PASS pref='zh_CN'  sys=en_US -> zh_CN
PASS pref='system' sys=en_US -> en_US   ★ 关键修复点
PASS pref='system' sys=zh_CN -> zh_CN
PASS pref='system' sys=ja_JP -> ja_JP
```

## 七、低风险项（需留意，当前无需改动）

### libarchive iconv 修补的字符串依赖
`CMakeLists.txt:249-263` 用 `string(REPLACE)` 匹配精确串：

```
iconv(cd, &itp, &remaining, &outp, &avail)   →   iconv(cd, (const char **)&itp, ...)
```

经核对，当前 libarchive 源 `archive_string.c:2092` **精确匹配**，修补会生效。
**风险点**：若将来子模块包中该行有空格/换行差异，替换会**静默失败**（不报错也不修）。
建议：若 Windows 侧出现 `iconv` 相关的 char\*\* 不匹配报错，优先检查此处是否命中。
