# 上游迁移链路缺口修复 —— 定位与验证记录

> 任务号：迁移保障　优先级：高　标签：汉化 / 迁移 / 基线完整性
> 记录日期：2026-10-02
> 影响面：**所有走「路线 B 干净树重放」的迁移**；路线 A（git merge）不受影响

---

## 一、背景

本次任务的目标是「确保所有改动在上游更新后可以快速迁移」。

核查迁移脚本 `scripts/migrate_to_upstream.sh` 时发现其自检基线（`migration_file_list()`）
**只覆盖 69 个 `src/` 源码文件**，而本仓库相对上游的改动远不止于此。

---

## 二、发现的三类缺口

### 2.1 构建层未覆盖（导致界面静默回退英文）

| 事实 | 数据 |
|---|---|
| `CMakeLists.txt` 上游版本 | **224 行** |
| `CMakeLists.txt` 本仓库版本 | **646 行** |
| 差距性质 | 构建体系**整体重写**，非小增量 |

`CMakeLists.txt` 里含汉化集成段（`IQMOL_STRICT_L10N`、`lrelease` 生成 `zh_CN.qm`），
但它**不在迁移清单内**。后果：目标树构建期不调用 `lrelease` →
不生成 `zh_CN.qm` → Qt 找不到译文 → **界面英文，且不报任何错**。

同时，`scripts/` 目录上游根本不存在（上游 `scripts/` 只有 5 个文件，无 `build_windows.sh`），
属纯新增资产，原脚本的收尾提示也漏了它。

### 2.2 界面资源未覆盖（导致半汉化）

`.ui` 文件定义的是界面元素本身（按钮文字、标签、标题）。
规则表按**源码原文精确匹配**工作，只能抓 `.C/.h` 里的 `tr()` 包裹，
**天然抓不到 `.ui`**。经核查：

```
src/ 下相对上游被修改的文件        91 个
其中被 ①②③ 机制覆盖              73 个
未被任何机制覆盖                  18 个（17 个 .ui + main.C + Math/CMakeLists.txt）
```

### 2.3 个别源码文件漏网

端到端验证时 selfcheck 报出 2 个文件不一致：

| 文件 | 根因 |
|---|---|
| `src/Qui/InputDialog.C` | 窗口标题是**拼接字符串** `"QChem Input File Editor - " + file.fileName()`，成果版改写为 `tr("QChem Input File Editor") + " - " + ...`。规则表按原文精确匹配必然落空，而该文件又不在 ③ 的清单内 |
| `src/Main/IQmolApplication.C` | ③ 补丁只记录了它的一处改动（`loadTranslations` 入口），成果版另有 5 处（Linux 多路径搜索、OpenBabel 便携布局探测）未被记录 |

---

## 三、根因：基线自证问题

最关键的一条教训：

> **原 selfcheck 的 69 项基线，本身就是由补丁清单生成的。**
>
> 也就是说，「用补丁清单当基线」这个做法天然看不见补丁之外的缺口 ——
> 相当于拿考卷答案对考卷，永远全对。

这解释了为什么此前 `--selfcheck` 一直报 `69/69 全部一致`，
却仍有三类改动根本没进迁移链路。

---

## 四、修复措施

### 4.1 新增两个补丁

| 补丁 | 步骤 | 覆盖 | 内容 |
|---|---|---|---|
| `patches/功能补丁-界面资源.patch` | ③.5 | 22 个文件 | 17 个 `.ui` 的文本汉化与 `font-size` px→pt、`main.C` 的 HighDPI 属性、`Math/CMakeLists.txt` 链接目标 |
| `patches/功能补丁-构建层.patch` | ④ | 4 个文件 | `CMakeLists.txt`（汉化集成段 + 十余项 Windows 构建修复）、`README.md`、`.gitignore`、CI |

### 4.2 补齐既有补丁

`patches/功能补丁-非机械改动.patch` 由 35 → **36 个文件**，补入
`IQmolApplication.C` 与 `InputDialog.C` 的漏网改动。

### 4.3 迁移脚本升级为六步

`scripts/migrate_to_upstream.sh` 现执行：

| 步骤 | 内容 |
|---|---|
| ① | 语言支持补丁（6 文件） |
| ② | tr() 规则表重放（487 条 / 58 文件） |
| ③ | 非机械改动补丁（36 文件） |
| ③.5 | 界面资源补丁（22 文件） |
| ④ | 构建层补丁（4 文件） |
| ⑤ | 资产自动同步（`translations/` `share/` `doc/` `docs/` `scripts/` `resources/`） |

新增能力：
- **⑤ 从"提示手工 cp"升级为脚本自动执行**，并保留目标树中上游独有的文件；
- 每个补丁步骤**独立预检**，失败时给出针对性处置建议而非静默跳过；
- 新增 `--no-assets` 参数（只做代码迁移）。

### 4.4 基线改用实际 diff 全集

selfcheck 基线从「补丁清单生成」改为**相对上游的实际改动全集**，
扩充至 **95 项**（源码 69 + 界面资源 22 + 构建层 4，去重后 95）。

## 六、遗留事项

- `patches/功能补丁-非机械改动.patch` 中 `src/Main/IQmolApplication.C` 存在 2 个同名
  `diff --git` 块（Git 支持，不影响应用）。如需整理可后续合并为单块。
- 构建层补丁冲突风险标注为 **high**：上游 224 行 vs 本仓库 646 行，
  上游一改 `CMakeLists.txt` 必然冲突，需人工按指南 §4.3 处理。
- 第三层治理（把构建修复隔离成独立 `cmake/*.cmake` include）仍未实施，
  本次仅把构建层改动从「人工合并」升级为「可自动检出不一致」。
