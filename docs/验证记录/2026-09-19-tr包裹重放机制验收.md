# tr() 包裹重放机制：实现与端到端验收

**日期**：2026-09-19
**类型**：方案验收
**定位**：第三层方案 **A 项**（tr() 脚本化重放）的完整验收记录
**结论**：✅ 通过。端到端重建 **35 / 42 个源码文件完全一致**，规则覆盖率 **100%**，幂等性双向验证成立。

---

## 一、要解决的问题

上游 IQmol 升级后，我们相对 `af7ff60` 的汉化改动会面临两类风险：

1. `git merge` 在翻译包裹密集的文件上产生大量冲突；
2. 即便自动合并成功，上游的新代码也可能把我们的包裹覆盖掉。

原先的 `wrap_tr.py` 是**行号驱动**的一次性脚本（只服务 `MainWindow.C`，硬编码
行号表）。上游在文件前插入一行，全部行号偏移，脚本立即失效。

**目标**：把翻译包裹改造成**内容驱动、可幂等重放**的规则表，使上游升级后能
一条命令重建。

## 三、机制要点（4 个关键设计）

### 3.1 三元组键：同一字面量多形态

`MainWindow.C` 的 `Save` 同时以两种形态出现：

```cpp
messageBox.addButton(tr("Save"), QMessageBox::AcceptRole)   // call:messageBox.addButton
name = tr("Save");                                           // bare
```

规则表键为 `(路径, 字面量, 形态)`，两处各占一行。**早期二元组键漏掉其中一种**，
本次修正后覆盖。

### 3.2 count 语义 B：最终包裹总数（幂等的关键）

```cpp
// ExcitedStatesConfigurator.C
第 341 行  setLabel(tr("Rel. Strength"))   ← 上游已自带
第 345 行  setLabel("Rel. Strength")       ← 裸的，由我们包裹
```

- **语义 A**（数 diff 新增行的包裹数）→ `count=1` → 重放时判定"仍有 1 处未包"
  → **再包一次，不幂等**；
- **语义 B**（成果文件中最终包裹总数）→ `count=2` → 重放补 `2 - 1 = 1` 处 → 幂等 ✅。

### 3.3 补足式 vs 构造式

| 形态 | 上游原文 | 动作 |
|---|---|---|
| `call:` / `bare` | 常有部分 `tr()` | **补足**裸字面量的包裹 |
| `translate:<上下文>` | 恒为裸字面量 | **构造** `QCoreApplication::translate(...)`，并自动注入 `#include <QCoreApplication>` |

新增的 `translate:` 形态专为 `UndoCommands.C` 而设（`QUndoCommand` 非 QObject，
没有 `tr()`），使该文件残余差异从 **21 行降至 1 行**。

### 3.4 函数上下文精确定位（品牌名陷阱）

```cpp
setWindowTitle(tr("IQmol"));                       // 包裹
QMessageBox(..., "IQmol", tr("Save Changes?"));    // 不包裹
```

不能用"全局排除名单"处理品牌名——会漏掉该包的那处。正确做法是尊重 `call:`
上下文的函数名约束。

## 四、验收方法与结果

### 4.1 方法

```
建干净上游基线：git worktree add /tmp/replaytest af7ff60
        ↓
应用功能补丁：git apply patches/功能补丁-语言支持.patch
        ↓
执行重放：python3 scripts/i18n/replay_tr.py --apply
        ↓
逐文件 diff 比对：/tmp/replaytest/* vs 成果仓库/*
```

### 4.2 结果

| 指标 | 数值 |
|---|---|
| 规则条数 | 250（覆盖 36 个文件） |
| diff 中 tr()/translate() 处数 | 172 |
| 规则覆盖率 | **172 / 172 = 100%** |
| 上游基线重放改动量 | 160 处 / 33 个文件 |
| **端到端重建完全一致** | **35 / 42 文件** |
| 规则表单独重放一致 | 29 / 36 文件（+ 6 个功能补丁文件） |
| 幂等性（成果仓库 dry-run） | **0 改动** ✅ |
| 幂等性（上游基线二次重放） | **0 改动** ✅ |

### 4.3 剩余差异（7 个文件 / 24 行，全部已定性）

| 文件 | 残余行数 | 类别 |
|---|---|---|
| `src/Viewer/UndoCommands.C` | 1 | 拼接 → 占位符重构 |
| `src/Configurator/MullikenDecompositionsDialog.C` | 2 | 拼接 → 占位符重构 |
| `src/Qui/GeometryConstraint.C` | 2 | 跨行拼接 → 占位符重构 |
| `src/Layer/GeminalOrbitalsLayer.C` | 4 | 拼接 → 占位符重构 |
| `src/Layer/MoleculeLayer.C` | 4 | 常量 → 可翻译字面量 |
| `src/Configurator/ConstraintConfigurator.C` | 6 | 拼接 → 占位符重构 |
| `src/Configurator/SurfaceAnimatorDialog.C` | 6 | 拼接 → 占位符重构 |

这 7 个文件的改动**超出机械包裹的表达能力**：需要把 `"A " + var` 改写成
`tr("A %1").arg(var)`（让翻译系统处理插值），或把宏常量替换为字面量（才能被
`lupdate` 提取）。属语义级重构，规则表无法也不应表达。

> 相比改造前（7 个文件、差异未量化、`UndoCommands.C` 差异 21 行），
> 现已是**差异定位到 1~6 行**的收敛状态。

## 五、上游升级操作流程

```bash
bash scripts/sync_upstream.sh --merge                        # 1. 合并上游
git apply patches/功能补丁-语言支持.patch                     # 2. 重放功能补丁
python3 scripts/i18n/replay_tr.py                            # 3. dry-run 审阅
python3 scripts/i18n/replay_tr.py --apply                    # 4. 重放翻译包裹
git diff --stat                                              # 5. 复核（应仅 7 个文件有残余差异）
# 6. 人工处理 §4.3 的 7 个语义重构点（差异点已定位）
bash scripts/build_windows.sh                                # 7. 构建验证
```
