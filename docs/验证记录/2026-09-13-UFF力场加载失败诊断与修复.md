## 1. 问题现象

Windows 下编译链接**完全成功**，程序启动后中文界面正常，但执行「计算 → 能量」时弹出错误对话框：

```
Failed to load force field: UFF
Unable to compute energy
BABEL_DATADIR environment variable may not be set correctly.
```

该提示的代码位置为 `src/Layer/MoleculeLayer.C:2080-2095`，触发条件是：

```cpp
OBForceField* forceField = OBForceField::FindForceField(obff);
if (!forceField) {
   // 弹出上述提示
}
```

即 `FindForceField("UFF")` 返回了 `NULL`。

---

## 2. 排除项（先证明不是数据问题）

提示文案把矛头指向 `BABEL_DATADIR`，但实测数据文件是齐的：

| 检查项 | 结果 |
| --- | --- |
| `build/share/openbabel/` 文件数 | 63 |
| `modules/openbabel/data/` 文件数 | 63 |
| `build/share/openbabel/UFF.prm` | 存在，12573 字节 |
| 构建产物中 `.obf` 插件文件数 | 0（静态构建，插件内联） |

同时核对了 OpenBabel 的数据查找实现 `modules/openbabel/src/tokenst.cpp:192` `OpenDatafile()`，其查找顺序为：

1. 当前工作目录
2. `${BABEL_DATADIR}/<BABEL_VERSION>/<文件名>`
3. `${BABEL_DATADIR}/<文件名>`

第 3 条即扁平目录，**本身可用**。因此**数据目录的布局与版本子目录都不是问题**，`BABEL_DATADIR` 也确实指向了 `build/share/openbabel`（由 `IQmolApplication.C:198-207` 在 Windows 下从 `applicationDirPath()` 上跳一级推导）。

结论：**这不是数据文件问题，提示文案具有误导性。**

---

## 3. 真正根因：静态插件自注册对象被链接器丢弃

### 3.1 OpenBabel 的插件注册机制

OpenBabel 的力场、文件格式、描述符、指纹等全部采用**全局对象自注册**，不以显式函数调用注册。以 UFF 为例，`modules/openbabel/src/forcefields/forcefielduff.cpp:579`：

```cpp
//Make a global instance
OBForceFieldUFF theForceFieldUFF("UFF", true);
```

该全局对象的构造函数把实例写入 `OBForceField::Map()` 静态表（`include/openbabel/plugin.h` 的 `MAKE_PLUGIN` 宏）。

### 3.2 链接器的成员提取规则

`BUILD_SHARED_LIBS OFF` 时，这些 `.cpp` 被编成静态库 `openbabel.a` 的成员目标文件。GNU ld 提取静态库成员的唯一依据是**符号引用**：

> 只有当静态库中某个成员目标文件定义了当前未解析的符号时，该成员才会被链入。

`forcefielduff.o` 中**不存在被任何地方引用的符号** —— 它的全部作用是全局构造函数的副作用。于是该 `.o` 被整体丢弃，自注册从未执行，`OBForceField::Map()` 中根本没有 `"UFF"` 条目，`FindType("UFF")` 返回 `NULL`。

**这是静默失效：编译、链接、启动全程无任何报错。**

### 3.3 为什么 Linux 上没暴露

本次修复验证时发现，Linux 沙箱环境中 CMake 的 `openbabel` 目标解析到了**系统动态库** `/usr/lib/x86_64-linux-gnu/libopenbabel.so.7.0.0`，动态库会完整加载其全部内容，不适用静态库的成员丢弃规则，因此该平台表现为正常。只有真正使用项目内静态 `openbabel` 的 Windows 构建才会踩中。

---

## 4. 修复方案

在 `CMakeLists.txt` 中用 `--whole-archive` 包裹 `openbabel`，强制链入其全部目标文件：

```cmake
if (WIN32 AND NOT BUILD_SHARED_LIBS)
   if (TARGET openbabel)
      target_link_libraries (${targetName}
         -Wl,--whole-archive
         "$<TARGET_FILE:openbabel>"
         -Wl,--no-whole-archive
      )
   endif()
else()
   if (NOT BUILD_SHARED_LIBS AND TARGET openbabel)
      target_link_libraries (${targetName}
         -Wl,--whole-archive
         "$<TARGET_FILE:openbabel>"
         -Wl,--no-whole-archive
      )
   else()
      target_link_libraries (${targetName} openbabel)
   endif()
endif()
```

同时移除了原链接列表中裸写的 `openbabel`，避免重复链接。

## 5. 验证方法

构造最小可复现工程：把「注册对象」与「查找函数」拆到**不同**目标文件，还原被丢弃的条件。

`registry.cpp`（查找函数，被 main 引用）：
```cpp
std::map<std::string,int>& Reg() { static std::map<std::string,int> m; return m; }
```

`uff.cpp`（全局自注册，无任何外部引用）：
```cpp
std::map<std::string,int>& Reg();
struct AutoReg { AutoReg(const char* n){ Reg()[n]=1; } };
namespace { AutoReg theUFF("UFF"); }
```

`main.cpp`：
```cpp
int main(){ printf("UFF found: %s\n", Reg().count("UFF") ? "YES" : "NO"); }
```

链接方式对比：

| 链接方式 | 运行结果 |
| --- | --- |
| 普通链接 `-lplug` | `UFF found: NO` ← **精确复现用户现象** |
| `-Wl,--whole-archive ./libplug.a -Wl,--no-whole-archive` | `UFF found: YES` ← **修复生效** |

Sandbox 内 Linux 增量构建同时验证：`--whole-archive` 生效、链接通过、`Generated 1519 translation(s) (1519 finished and 0 unfinished)`。

## 7. Windows 端复现修复的步骤

```bash
cd /d/IQmol/IQmol-src
curl -sLo CMakeLists.txt "https://ghfast.top/https://raw.githubusercontent.com/stone-Glitch/IQmol-for-Chinese/master/CMakeLists.txt"
curl -sLo scripts/deploy_windows.sh "https://ghfast.top/https://raw.githubusercontent.com/stone-Glitch/IQmol-for-Chinese/master/scripts/deploy_windows.sh"
grep -n "whole-archive" CMakeLists.txt   # 应能看到 4 处以上

rm -f build/CMakeCache.txt               # 只删缓存，不要删整个 build
bash scripts/build_windows.sh            # 会检测到 CMakeLists.txt 更新并自动重新 configure
bash scripts/deploy_windows.sh
cd build/bin && ./IQmol.exe
```

预期：`configure` 阶段打印 `[IQmol] 已对 openbabel 启用 --whole-archive`；部署阶段打印 `力场参数已就位: UFF.prm / ghemical.prm / gaff.prm / mm2.prm`；启动后执行能量计算不再报 `Failed to load force field: UFF`。

## 8. 经验沉淀

> **静态库里"只有全局构造函数副作用"的目标文件会被 GNU ld 静默丢弃。**

凡是采用「全局对象自注册」模式的第三方库（OpenBabel 插件、Qt 插件静态版、各类 factory 注册表），静态链接到可执行文件时都必须用 `--whole-archive` 包裹，或使用 `--undefined=<符号>` 强制拉入。这类问题**不会在编译链接期报错**，只会在运行期表现为「功能莫名其妙不存在」，且常被误导到配置/路径方向排查。

同时提醒：`OBGlobalDataBase::Init()` 中存在一个上游笔误 —— `data.cpp:685` 在 `if` 内重新声明了同名变量 `string fn_open = OpenDatafile(...)`，遮蔽了外层变量，使随后的 `if (fn_open != "" && (ifs))` 恒为假。这不影响本次问题（UFF 走的是 `ParseParamFile()` 中的独立 `OpenDatafile` 调用），但排查 OpenBabel 数据加载问题时需注意这一点，避免被带偏。
