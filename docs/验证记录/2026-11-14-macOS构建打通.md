## 三、最后两组未定义符号的根因

### 3.1 `CairoPainter::*`

`modules/openbabel/src/formats/formats.cmake:165` 在 `CAIRO_FOUND` 时把 `png2format`
加入格式列表，并把 `../depict/cairopainter.cpp` 登记为 `png2format_additional_sources`。
但静态构建分支（`src/CMakeLists.txt` 的 `foreach(format ${formats})`）**只取
`formats/${format}.cpp`，忽略 `_additional_sources`**，于是 `cairopainter.cpp` 从未
编入 `libopenbabel.a`，而 `png2format.cpp` 又引用了
`CairoPainter::{CairoPainter, SetPenWidth, WriteImage, ~CairoPainter}`。

根 `CMakeLists.txt` 的「补齐静态构建漏编格式附加源」一节注释本就写明
「本构建默认不带 Cairo」，Linux/Windows 均如此。macOS 之所以撞上，只因
`macos-15` 镜像**预装了 cairo**，`CAIRO_FOUND` 变真。

**修法**：configure 加 `-DCMAKE_DISABLE_FIND_PACKAGE_Cairo=TRUE`，使三平台行为一致。
IQmol 自身出图走 `Viewer::saveImage`，不依赖 OpenBabel 的 `png2format`。

### 3.2 `_libiconv*`

`modules/openbabel/include/iconv.h` 是 GNU libiconv 附带的那份，在未定义
`LIBICONV_PLUG` 时会把符号重命名：

```c
#ifndef LIBICONV_PLUG
#define iconv_open libiconv_open
#endif
```

而根 CMakeLists 里 `include_directories(modules/openbabel/include)` 排在最前，导致
libarchive 的 `archive_string.c` 编出 `_libiconv_open` / `_libiconv` / `_libiconv_close`
引用。Darwin 的 libiconv 只导出 `iconv_*`（由 libSystem 提供），没有 GNU 前缀符号。

**修法**：`elseif (APPLE)` 分支加 `add_compile_definitions(LIBICONV_PLUG)` 关闭重命名，
并 `find_library(IQMOL_ICONV_LIBRARY NAMES iconv)` 显式补链。只在本分支设置，
Linux/Windows 行为不变。

## 四、方法：本地 libc++ 复现，避免盲试 CI

第 8 轮的两个编译错误，本质是「Windows/Linux CI 能过、只有 macOS 失败」，靠反复推
CI 试错代价太高（每轮 4~9 分钟）。本地建了等价环境：

```bash
sudo apt-get install -y libc++-dev libc++abi-dev      # clang 18 + /usr/include/c++/v1
# 用 cmake -P 跑真实的 modules/openbabel/src/config.h.cmake 的 configure_file，
# 模拟 macOS（不 set HAVE_CONIO_H），生成 babelconfig.h
```

保真度自检：未打补丁时报

```text
plugin.h:41:42: error: no template named 'binary_function' in namespace 'std'; did you mean '__binary_function'?
```

**与 CI 一字不差**，故后续修复在本地即可验证。

本地全量基线（打补丁后）：

| 扫描面 | 文件数 | 剩余失败 | 结论 |
|---|---|---|---|
| openbabel `src/**/*.cpp` | 259 | 26 | 全部为缺失外部依赖（Eigen/wxWidgets/RDKit/cairo/rapidjson/rpc/xdr）或构建期生成头，**无 C++17 兼容问题** |
| IQmol `src/**/*.C` | 293 | 19 | include 路径与可选依赖；`binary_function` 从 4 处降到 **0** |

## 五、后续待办

1. **真机 GUI 启动验证**：下载 artifact 在真实 Mac 上跑一遍，覆盖打开分子 / 轨道渲染 /
   保存图片。这是 macOS 从「实验性」升级的唯一缺口。
2. **签名与公证**：需 Apple 开发者证书（`mac_deploy.sh` 内含 `codesign` + `notarytool`），
   CI 无凭据，只能发版时手动或加 secret。
3. **`qt@5` 弃用**：Homebrew 已标记，**2027-05-19 停用**。届时需评估 Qt6 迁移或改用
   aqtinstall / 自建 bottle。
4. **Node.js 20 弃用警告**：`actions/checkout@v4.2.2` 与 `actions/upload-artifact@v4`
   被强制跑在 Node 24 上，后续升 major 版本消除。
5. **arm64 runner 排队长**：GitHub 提示容量受限，必要时考虑 `macos-15-intel` 或自托管。
