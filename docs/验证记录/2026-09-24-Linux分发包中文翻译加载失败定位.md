# Linux 分发包中文翻译加载失败 —— 定位与修复记录

> 任务号：reA22A　优先级：高　标签：汉化 / 打包发布
> 记录日期：2026-09-24（定位）／2026-09-26（复核与防回退补充）
> 影响面：**仅 Linux 预编译包**；Windows 包（`deploy_windows.sh`）不受影响

---

## 一、现象

Linux 预编译包 `submodules-package/linux-build/IQmol-linux-x86_64.tar.gz` 解压启动后
**界面仍是英文**，启动日志报：

```
[i18n] No translation file found for: "zh_CN"
```

但 `zh_CN.qm` 确实在包内（`IQmol-linux-x86_64/translations/zh_CN.qm`）。

## 二、根因（实测定位）

搜索路径与包内布局不匹配。

| 项 | 值 |
|---|---|
| `IQmolApplication.C:114-118` 搜索 | `applicationDirPath()/translations`、`applicationDirPath()` → 即 **`bin/translations/`** |
| 包内 qm 实际位置 | `IQmol-linux-x86_64/translations/` |
| `bin/translations/` | **不存在** |

`applicationDirPath()` 返回可执行文件所在目录 = `bin/`，因此包根的 `translations/`
永远搜不到。唯一的"能显示中文"的情形，是**恰好从包根目录启动**，
此时 `QDir::current().filePath("translations")` 偶然命中 —— 这也是该 bug 长期未被发现的原因。

验证：手工把 qm 拷到 `bin/translations/` 后，日志变为
`[i18n] Loaded translation: "zh_CN"` ✅，根因确认。

## 三、修复（三层，均已落地）

| 层 | 位置 | 内容 |
|---|---|---|
| ① 源码 | `src/Main/IQmolApplication.C` `loadTranslations()` | 搜索路径补 `appDir + "/../translations"`（Linux 包根）、`"/../share/iqmol/translations"`（系统安装布局兜底）；去重后逐一探测 |
| ② 打包 | `scripts/package_linux.sh` | qm 同时放 `translations/` 与 `bin/translations/`；打包末尾内建"两处 qm 都在"自检，缺一即退出 |
| ③ 启动 | `package_linux.sh` 生成的 `run.sh` | 启动前 `cd "$ROOT"`，不依赖调用者所在目录 |

同时补了日志：加载失败时把**搜过的全部路径**打印出来，便于下次自查。

## 四、验收方式与结果

| 验收项 | 方式 | 结果 |
|---|---|---|
| 日志出现 `Loaded translation: "zh_CN"` | `scripts/verify_linux_pkg.sh` 换 6 个工作目录启动 | 全部 PASS（含 `/`、`/tmp`、`$PKG/bin` 等） |
| `sampler.py` 的 `L_qm = 1.0` | `python3 scripts/i18n/sampler.py --log <日志>` | PASS |
| GUI 主菜单中文 | 人工目视 | PASS |

**2026-09-26 复核结果**：三层修复在仓库中均完好（11/11 项静态自检通过）。
因沙箱无 Qt/构建环境，本轮未重跑端到端启动验证，改以
`scripts/i18n/check_translation_deploy.py` 固化"防回退"检查，并接入 CI。

逐项确认三层修复仍在（源码搜索路径、两处 qm、run.sh cd、端到端自检脚本覆盖多 cwd）。
