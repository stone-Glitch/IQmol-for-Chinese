### 2.2 `doc/编译-照着敲.md`（主要修订）

| 项 | 修改前 | 修改后 |
|---|---|---|
| 产物路径 | `build/IQmol.exe` | `build/bin/IQmol.exe` |
| 翻译文件 | `build/translations/zh_CN.qm` | `build/bin/translations/zh_CN.qm` |
| 部署方式 | 手写 `windeployqt` + 自我复制笔误 | 改用 `deploy_windows.sh`，附目录约定表 |
| 脚本能力 | 缺配置指纹自检、uninstall 修复 | 已补齐 |
| 首次编译耗时 | 20~40 分钟 | 20~60 分钟（插件改为静态内联） |
| 网络下载 | 直连 `raw.githubusercontent.com` | 统一走 `ghfast.top` 镜像 |

**排查表新增 6 类本轮真实报错**：

| 现象 | 根因 |
|---|---|
| `undefined reference to __imp__ZN9QGLViewer...` | 静态库头文件按 DLL 导入展开，缺 `QGLVIEWER_STATIC` |
| `undefined reference to __imp_glStencil*` / `gluNewQuadric` | CMake 3.14+ 不再设 `OPENGL_LIBRARIES`，OpenGL/GLU 未链接 |
| `No rule to make target 'libopenbabel.a'` | `--whole-archive` 误用 `$<TARGET_FILE:...>` 破坏依赖跟踪 |
| `Unable to find OpenBabel plugins` | 子模块 `BUILD_SHARED` 未与顶层同步，插件未内联 |
| `Failed to load force field: UFF` | 静态库中插件自注册对象被链接器丢弃 |
| 改了 `CMakeLists.txt` 但行为没变 | 构建未重新 configure |

并新增条目「`bash: scripts/build_windows.sh: No such file or directory`」——
本地 `scripts/` 缺文件（仓库后续才加入）。

> 另加一条**排查心法**：很多报错的提示文案本身是误导性的。例如
> `Failed to load force field` 提示「`BABEL_DATADIR` 可能没设对」，
> 实际原因通常是构建配置。遇到含「环境变量/路径」提示的报错时，
> 先确认构建配置是否真的生效，再查运行环境。
