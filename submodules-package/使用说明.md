# IQmol 子模块离线包（Windows 用户专用）

GitHub 子模块仓库体积大、国内网络经常断连（`git submodule update` 卡在 6%、
或 `Failed to connect to github.com:443`），所以这里提供**打包好的完整子模块源码**：
下载 → 解压到仓库根目录 → 直接构建，完全跳过联网克隆。

## 一、下载（共 6 个文件）

| 文件 | 大小 | 用途 |
|------|------|------|
| **`IQmol-submodules.tar.gz`** | **72 MB** | 完整子模块源码（单文件，不用合并） |
| `extract_submodules.bat` | 3.5 KB | 校验 + 解压脚本（可选，推荐一起下） |
| **`IQmol-openbabel-deps.tar.gz`** | **1.2 MB** | OpenBabel 的 3 个构建期依赖（maeparser/coordgen/rapidjson），**必须额外下** |
| **`IQmol-openbabel-fix.tar.gz`** | **32 MB** | 补 `libinchi/`、`test/` + 给 uninstall 加重名保护，**必须额外下** |
| **`IQmol-openbabel-formats-fix.tar.gz`** | **1.3 MB** | 补 `src/formats/` 全部格式源文件（xml / json 等 128 个 `.cpp`），**必须额外下** |
| **`IQmol-data-headers.tar.gz`** | **467 KB** | OpenBabel 数据头预生成文件（`bondtyp.h` 等 9 个），MinGW 无法执行 perl 生成链，**必须额外下** |

> ⚠️ **解压工具警告：请用 `tar` 命令解压**（MSYS2 / MINGW64 终端，或 Windows 自带 `tar.exe`），
> **不要用 360 压缩 / 7-Zip / WinRAR 的图形界面解 `.tar.gz`。**
> 图形工具解 `.tar.gz` 会**静默丢文件**——本项目已连续两轮因此缺文件（先缺
> `libinchi`/`test`，再缺 `formats/xml`、`formats/json`），且常只解出中间层 `.tar`
> 需要二次解压。命令行 `tar -xzf` 是唯一可靠方式。

## 二、操作步骤

### 1. 把两个文件放同一个文件夹

例如 `D:\Downloads\`，里面应该有：

```
IQmol-submodules.tar.gz
extract_submodules.bat
```

### 2. 双击 `extract_submodules.bat`

它会：检查文件在不在 → 校验大小和 MD5 → 提示解压命令。
校验不通过会明确告诉你是哪个文件没下全。

### 3. 带路径运行，一步解压到位

在 **cmd 命令提示符**里（不是 PowerShell，看提示符：`C:\>` 是 cmd，`PS C:\>` 是 PowerShell）：

```bat
cd /d D:\Downloads
extract_submodules.bat "D:\IQmol"
```

把 `"D:\IQmol"` 换成你**仓库根目录**的实际路径。

> ⚠️ **强烈建议仓库放在短路径下**，比如 `D:\IQmol`。
> Windows 有 260 字符路径上限，子模块源码目录层级很深，
> 路径太长会在解压时报 `filename too long` 之类的错误。

### 4. 手动版（不用脚本）

**MSYS2 终端（最稳，推荐）：**

```bash
cd /d/IQmol
tar -xzf /d/Downloads/IQmol-submodules.tar.gz
```

**Windows cmd / PowerShell：**

```bat
cd /d D:\IQmol
tar -xzf D:\Downloads\IQmol-submodules.tar.gz
```

**校验（可选）：**

```bat
certutil -hashfile IQmol-submodules.tar.gz MD5
```

| 项目 | 值 |
|------|-----|
| 大小 | **75,761,144** 字节 |
| MD5  | **6a04b71aa0c29dfe43881830805220c7** |

对不上就是没下全，重新下载即可（支持续传）。

## 三、验证解压结果

```bat
dir modules
```

应该看到 9 个目录：

```
HighFive  hdf5  libarchive  libQGLViewer  libssh2  libxml2  openbabel  openmesh  yaml-cpp
```

再确认关键文件在：

```bat
dir modules\hdf5\CMakeLists.txt
dir modules\openbabel\CMakeLists.txt
dir modules\yaml-cpp\CMakeLists.txt
```

> 压缩包内部顶层就是 `modules\`，所以**必须解压到仓库根目录**，
> 不是解压到 `modules` 里面——这样才会和仓库已有的 `modules` 目录合并。

## 三之二、额外解压 OpenBabel 依赖包（不能省）

OpenBabel 在**编译阶段**会联网拉取 3 个依赖（maeparser / coordgenlibs / rapidjson），
国内网络拉不到会直接 `FATAL_ERROR`。刚才下的 `IQmol-openbabel-deps.tar.gz`
已经按 `external/` 正确布局摆好，解压到 **`modules\openbabel\`** 即可离线构建：

在 **cmd** 里：

```bat
cd /d D:\IQmol\modules\openbabel
tar -xzf D:\Downloads\IQmol-openbabel-deps.tar.gz
```

解压后 `modules\openbabel\external\` 下应有：

```
maeparser-v1.2.3\maeparser\CMakeLists.txt
coordgen-master\coordgen\CMakeLists.txt
rapidjson-1.1.0\CMakeLists.txt
```

（不解压也能编，但 CMake 会在编 OpenBabel 时尝试联网下载，网络不好就崩。）

---

## 三之三、解压两个 OpenBabel 补丁包（不能省）

子模块解压后，OpenBabel 还会因**文件缺失**和**目标重名**两类问题让 configure 失败：

| 报错 | 对应补丁包 |
|---|---|
| `add_subdirectory ... not an existing directory`（`libinchi` / `test`） | `IQmol-openbabel-fix.tar.gz` |
| `uninstall ... target with the same name already exists`（与 yaml-cpp 重名，CMP0002） | `IQmol-openbabel-fix.tar.gz` |
| `No SOURCES given to target: pubchem / xmlformat / cmlreactformat / chemdoodlejsonformat / pubchemjsonformat` | `IQmol-openbabel-formats-fix.tar.gz` |

两个包都解压到 **`modules\openbabel\`**：

```bat
cd /d D:\IQmol\modules\openbabel
tar -xzf D:\Downloads\IQmol-openbabel-fix.tar.gz
tar -xzf D:\Downloads\IQmol-openbabel-formats-fix.tar.gz
```

> ⚠️ **顺序陷阱**：若你重新解压了 `IQmol-submodules.tar.gz`，它会把
> `openbabel\CMakeLists.txt` 覆盖回**未修版**，uninstall 保护随之丢失、
> 174 行冲突会原样复现。顺序必须是：**先完整包 → 再打上面两个补丁包**。

---

## 三之四、解压数据头包（不能省）

MinGW 下 OpenBabel 无法执行 perl 数据头生成链（`bondtyp.h` 等 9 个头文件
生成失败会导致大批 `'BondTypeData' was not declared` 编译错误）。
`IQmol-data-headers.tar.gz` 里是预生成好的数据头（v2：同时放入
`data\pregen\` 和 `src\` 两处），解压到**源码根目录**：

```bat
cd /d D:\IQmol
tar -xzf D:\Downloads\IQmol-data-headers.tar.gz
```

解压后应能看到 `modules\openbabel\data\pregen\`（9 个 `.h`）和
`modules\openbabel\src\` 下的同名头文件。`build_windows.sh` 会自动检测
并替换 OpenBabel 的 `data/CMakeLists.txt` 为预生成头方案。

---

## 四、开始构建

> **CMake 版本**：`build_windows.sh` 检测到 CMake 4.x 时会自动下载
> portable CMake 3.31 并使用，无需手动处理。若手动配置，请用 3.x
>（子模块最低要求 < 3.5、OpenBabel 用 `CMP0042 OLD`，CMake 4.0+ 直接拒绝）。

```bat
cd /d D:\IQmol
bash build_windows.sh
```

（在 MINGW64/MSYS2 终端里运行；脚本会自动完成 configure、编译、
错误提取与构建树自愈。）

---

## ⚠️ 四个坑

1. **别用 360 压缩 / 7-Zip / WinRAR 的图形界面解 `.tar.gz`** — 会**静默丢文件**，
   本项目已连续两轮因此缺文件（先缺 `libinchi`/`test`，再缺 `formats/xml`、`formats/json`）。
   一律用 `tar -xzf`（MSYS2 / MINGW64 终端，或 Windows 自带 `tar.exe`）。
2. **别再跑 `git submodule update --init --recursive`** — 会重新联网克隆，覆盖掉刚解压的文件。
3. **之前克隆失败留过半截目录的**，先清理再解压：
   ```bat
   git submodule deinit -f --all
   ```
4. **路径别太长** — 仓库放 `D:\IQmol` 这种短路径，别放
   `D:\我的文档\项目\化学软件\IQmol-for-Chinese\...`。
